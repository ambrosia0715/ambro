
# Cursor AI 에디터 200% 활용하기: 워크플로우 혁신 가이드

개발자들 사이에서 가장 핫한 에디터를 꼽으라면 단연 **Cursor**일 것입니다. VS Code를 기반으로 만들어져 기존 확장 프로그램과 키바인딩을 그대로 가져올 수 있으면서도, 강력한 LLM(Large Language Model) 기능을 내장하여 코딩 생산성을 비약적으로 높여줍니다. "코드 짜줘"라는 단순한 요청을 넘어, 프로젝트 전체를 이해하는 AI 페어 프로그래머와 함께 일하는 경험을 제공합니다.

이 글에서는 Cursor를 처음 설치하는 것부터, 실무 워크플로우에 깊숙이 통합하여 생산성을 극대화하는 고급 기법까지 단계별로 소개합니다.

## 1. Cursor 설치와 초기 세팅

### 1.1 설치 방법

공식 사이트(cursor.com)에서 OS에 맞는 설치 파일을 다운로드합니다. macOS 사용자는 DMG 파일을 열어 Applications 폴더로 드래그하면 됩니다.

```bash
# macOS Homebrew를 사용하는 경우
brew install --cask cursor
```

최초 실행 시 VS Code 설정을 자동으로 가져올지 물어봅니다. 기존 VS Code 사용자라면 **Import Settings**를 선택하여 확장 프로그램, 테마, 키바인딩을 한 번에 마이그레이션할 수 있습니다.

### 1.2 모델 선택과 API 설정

`Settings > Models`에서 사용할 LLM을 선택합니다. Cursor Pro 구독자는 Claude Sonnet, GPT-4o 등을 바로 사용할 수 있고, 자체 API 키를 등록하여 다른 모델을 연결할 수도 있습니다.

```
# 추천 설정 조합
- 빠른 자동완성: Claude Haiku (속도 우선)
- 복잡한 리팩토링: Claude Sonnet (정확도 우선)
- 대규모 코드 생성: GPT-4o (긴 출력 안정적)
```

**팁:** 프로젝트 특성에 따라 모델을 바꿔가며 써보세요. 프론트엔드 UI 작업은 Claude가, 알고리즘이나 수학적 로직은 GPT-4o가 더 나은 경우가 많습니다.

## 2. 핵심 기능 세 가지 마스터하기

### 2.1 Cmd+K (인라인 편집)

에디터 내에서 코드를 선택하고 `Cmd+K`(Windows: `Ctrl+K`)를 누르면 AI에게 직접 지시를 내릴 수 있습니다. 선택한 코드의 문맥을 자동으로 파악하므로, 간결한 명령만으로 정확한 결과를 얻습니다.

```python
# 원본 코드를 선택한 후 Cmd+K로 지시
# "에러 핸들링을 추가하고 로깅을 넣어줘"

# Before
def fetch_user(user_id):
    response = requests.get(f"/api/users/{user_id}")
    return response.json()

# After (AI가 자동 생성)
def fetch_user(user_id: int) -> dict | None:
    try:
        response = requests.get(f"/api/users/{user_id}")
        response.raise_for_status()
        return response.json()
    except requests.exceptions.HTTPError as e:
        logger.error(f"HTTP error for user {user_id}: {e}")
        return None
    except requests.exceptions.ConnectionError:
        logger.error(f"Connection failed for user {user_id}")
        return None
```

### 2.2 Cmd+L (AI 채팅)

사이드바 채팅은 코드에 대해 질문하거나 복잡한 작업을 요청할 때 사용합니다. 핵심은 `@` 기호를 활용한 **컨텍스트 참조**입니다.

- `@파일명` — 특정 파일을 참조하여 질문
- `@폴더명` — 폴더 전체의 구조와 코드를 참조
- `@Codebase` — 프로젝트 전체를 검색하여 답변
- `@Docs` — 등록한 외부 문서를 참조
- `@Web` — 실시간 웹 검색 결과를 참조

```
# 실무 프롬프트 예시
@src/auth "현재 인증 로직에서 JWT 토큰 갱신 처리가 빠져있는 것 같아.
리프레시 토큰을 사용한 자동 갱신 로직을 추가해줘.
@src/api/client.ts 의 axios 인터셉터에 통합되어야 해."
```

### 2.3 Cmd+I (Composer - 멀티파일 편집)

Composer는 Cursor의 가장 강력한 기능입니다. 여러 파일을 동시에 생성하거나 수정할 수 있어, 새로운 기능을 통째로 만들 때 매우 유용합니다.

```
# Composer 프롬프트 예시
"사용자 프로필 수정 기능을 만들어줘.
- API 라우트: src/api/profile.ts
- React 컴포넌트: src/components/ProfileEdit.tsx
- 폼 검증: src/utils/validation.ts
- Zod 스키마와 React Hook Form을 사용해줘
- @src/types/user.ts 의 User 타입을 따라줘"
```

## 3. RAG 기반 코딩: 문맥을 활용하는 고급 기법

Cursor의 가장 큰 경쟁력은 **RAG(Retrieval-Augmented Generation)** 기반 코딩입니다. 내 프로젝트의 코드를 인덱싱하여 AI가 전체 구조를 파악하고, 관련 파일을 자동으로 참조하여 답변합니다.

### 3.1 문서 등록 (@Docs)

새로운 라이브러리를 쓸 때 브라우저와 에디터를 오가며 문서를 찾을 필요가 없습니다. `Settings > Features > Docs`에서 자주 쓰는 문서 URL을 등록하세요.

```
# 등록 추천 문서 목록
- Next.js: https://nextjs.org/docs
- Tailwind CSS: https://tailwindcss.com/docs
- Prisma: https://www.prisma.io/docs
- React Query: https://tanstack.com/query/latest/docs
```

등록 후 채팅에서 `@Next.js Docs 앱 라우터에서 서버 액션 사용법 알려줘`처럼 호출하면 최신 공식 문서 기반으로 정확한 코드를 생성합니다.

### 3.2 이미지 입력으로 UI 구현

디자인 시안(Figma 캡처, 스크린샷 등)을 채팅창에 드래그 앤 드롭하고 "이 디자인대로 컴포넌트를 만들어줘"라고 요청하면, Tailwind CSS 클래스가 적용된 완성도 높은 코드를 생성합니다. 색상 코드, 간격, 폰트 크기까지 시안에서 추출해줍니다.

## 4. 커스텀 규칙으로 팀 컨벤션 자동화

프로젝트 루트에 `.cursor/rules/` 디렉토리를 만들고 규칙 파일을 추가하면, AI가 코드를 생성할 때 항상 이 규칙을 따릅니다.

```markdown
# .cursor/rules/coding-standards.mdc

## 코딩 컨벤션
- TypeScript를 사용하고, any 타입 사용 금지
- 컴포넌트는 함수형으로 작성하고 export default 사용 금지 (named export만 허용)
- API 호출 시 반드시 에러 핸들링 포함
- 스타일링은 Tailwind CSS 사용 (인라인 스타일, CSS Modules 사용 금지)
- 상태 관리: 서버 상태는 React Query, 클라이언트 상태는 Zustand

## 파일/폴더 구조
- 컴포넌트: src/components/{도메인}/{컴포넌트명}.tsx
- 유틸: src/utils/{기능명}.ts
- API: src/api/{리소스명}.ts
```

매번 프롬프트에 "Tailwind 써줘", "TypeScript로 짜줘"라고 반복할 필요가 사라집니다.

## 5. 실무 워크플로우: 기능 개발부터 디버깅까지

### 5.1 새 기능 개발 플로우

```
1단계: Composer로 기능 뼈대 생성 (API + 컴포넌트 + 타입)
2단계: 생성된 코드 검토 → Cmd+K로 세부 수정
3단계: 채팅에서 @파일 참조하며 테스트 코드 요청
4단계: 터미널에서 테스트 실행 → 실패 시 에러 메시지 복사하여 채팅에 붙여넣기
5단계: AI가 수정안 제시 → 검토 후 적용
```

### 5.2 디버깅 플로우

터미널에서 에러가 발생하면 에러 메시지 옆의 **Auto Debug** 버튼을 클릭합니다. Cursor가 에러 로그, 관련 소스 코드, 스택 트레이스를 종합하여 원인을 분석하고 수정안을 제안합니다.

```bash
# 터미널에서 에러 발생 시
TypeError: Cannot read properties of undefined (reading 'map')
  at UserList (src/components/UserList.tsx:15:22)

# → Auto Debug 클릭하면 AI가 자동으로 분석:
# "users 데이터가 아직 로딩되지 않았을 때 map을 호출해서 발생하는 에러입니다.
#  옵셔널 체이닝이나 로딩 상태 체크를 추가하세요."
```

## 6. 자주 하는 실수와 해결법

| 실수 | 해결 방법 |
|------|-----------|
| 프롬프트가 너무 모호함 | 기술 스택, 파일 경로, 기대 동작을 구체적으로 명시 |
| 컨텍스트를 안 줌 | `@파일명`으로 관련 코드를 직접 참조 |
| 결과를 무조건 수락 | 반드시 diff를 검토하고, 이해 안 되는 코드는 설명을 요청 |
| 한 번에 큰 작업 요청 | 단계별로 나누어 요청하고 중간 결과를 확인 |
| .cursorrules를 안 씀 | 프로젝트 초기에 팀 컨벤션 규칙 파일을 반드시 작성 |

## 결론: AI 페어 프로그래머와 함께 일하기

Cursor는 단순한 도구의 변화가 아니라 **개발하는 방식의 패러다임 전환**을 의미합니다. 문법을 외우는 것보다 무엇을 만들지 정의하고, AI에게 정확한 맥락을 제공하는 능력이 점점 중요해지고 있습니다.

오늘 당장 실행할 수 있는 세 가지 액션 플랜을 제안합니다.

1. **Cursor 설치 후 기존 프로젝트 열기** — VS Code 설정을 가져오면 전환 비용이 거의 없습니다.
2. **`.cursor/rules/` 규칙 파일 작성** — 팀의 코딩 컨벤션을 AI에게 가르치세요.
3. **하루 한 기능을 Composer로 만들어보기** — 작은 것부터 시작하여 AI와의 협업 감각을 키우세요.
