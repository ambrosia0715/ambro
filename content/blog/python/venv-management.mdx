
# 파이썬 가상환경 관리의 모든 것: venv, virtualenv, conda, poetry

"분명 어제까진 잘 돌아갔는데?" — 파이썬 개발자라면 한 번쯤 겪어본 악몽입니다. 프로젝트 A에서 `requests 2.28`을 설치했더니, 프로젝트 B에서 사용하던 `requests 2.25`와 충돌이 나면서 갑자기 코드가 깨지는 상황. 이른바 **Dependency Hell(의존성 지옥)**입니다.

이 문제를 근본적으로 해결하는 도구가 **가상환경(Virtual Environment)**입니다. 이 글에서는 단순히 "이런 게 있다"를 넘어서, 각 도구를 직접 설치하고 사용하는 전 과정을 터미널 명령어와 함께 따라할 수 있도록 구성했습니다.

![Python Virtual Environments Comparison](assets/images/blog/python_venv.webp)

## 1. 가상환경이 필요한 이유

먼저 가상환경 없이 작업하면 무슨 일이 벌어지는지 직접 확인해봅시다.

```bash
# 시스템 전역에 패키지 설치
pip install pandas==1.5.3
pip install pandas==2.0.0  # 기존 1.5.3이 덮어씌워짐!
```

위처럼 전역 환경에 패키지를 설치하면, 모든 프로젝트가 같은 버전을 공유하게 됩니다. 프로젝트별로 다른 버전이 필요하면 매번 재설치해야 합니다. 가상환경은 이 문제를 프로젝트별 독립 공간을 만들어서 해결합니다.

**가상환경의 3가지 핵심 이점:**

| 이점 | 설명 | 예시 |
|------|------|------|
| 의존성 격리 | 프로젝트마다 독립적인 패키지 버전 유지 | A는 Django 3.2, B는 Django 4.2 |
| 재현성 확보 | 파일 하나로 어디서든 동일 환경 구축 | `requirements.txt`, `poetry.lock` |
| 시스템 보호 | 전역 Python 환경을 오염시키지 않음 | sudo pip install 사고 방지 |

## 2. venv — 파이썬 내장 도구

Python 3.3부터 표준 라이브러리에 포함된 모듈입니다. 별도 설치가 전혀 필요 없어 가장 가볍고 빠르게 시작할 수 있습니다.

### 실습: venv로 프로젝트 세팅하기

```bash
# 1단계: 프로젝트 디렉토리 생성
mkdir my_project && cd my_project

# 2단계: 가상환경 생성 (.venv 폴더가 만들어짐)
python3 -m venv .venv

# 3단계: 가상환경 활성화
# macOS / Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (CMD)
.venv\Scripts\activate.bat
```

활성화되면 터미널 프롬프트 앞에 `(.venv)`가 표시됩니다. 이 상태에서 pip로 설치하는 모든 패키지는 `.venv` 폴더 안에만 저장됩니다.

```bash
(.venv) $ pip install requests==2.28.0
(.venv) $ python -c "import requests; print(requests.__version__)"
# 출력: 2.28.0

# 설치된 패키지 목록을 파일로 저장
(.venv) $ pip freeze > requirements.txt

# 다른 환경(동료 PC, 서버 등)에서 동일하게 복원
(.venv) $ pip install -r requirements.txt

# 가상환경 비활성화
(.venv) $ deactivate
```

### 흔한 실수와 해결법

```bash
# 실수 1: 가상환경 폴더를 Git에 커밋해버림
# 해결: .gitignore에 추가 (수백MB 폴더가 저장소에 올라가는 것을 방지)
echo ".venv/" >> .gitignore

# 실수 2: 활성화 안 하고 pip install 실행
# 확인 방법: which python 으로 경로가 .venv 안을 가리키는지 확인
which python
# 올바른 출력: /Users/you/my_project/.venv/bin/python
# 잘못된 출력: /usr/bin/python (시스템 전역 → 위험!)

# 실수 3: 가상환경 폴더를 다른 경로로 이동
# 가상환경은 생성된 절대경로에 종속됩니다. 이동하면 깨집니다.
# 해결: 이동하지 말고, 새 위치에서 다시 생성하세요.
```

## 3. Conda — 데이터 사이언스의 표준

Conda는 패키지 관리자이자 환경 관리자입니다. 파이썬뿐 아니라 C/C++ 바이너리 의존성까지 처리하며, Python 인터프리터 버전 자체도 전환할 수 있습니다.

### 실습: Conda 환경 만들기

```bash
# Miniconda 설치 후 진행 (anaconda.com에서 다운로드)

# Python 3.11 환경 생성
conda create -n ml_project python=3.11 -y

# 환경 활성화
conda activate ml_project

# conda로 패키지 설치 (바이너리 최적화 버전 제공)
conda install numpy pandas scikit-learn -y

# pip와 혼용도 가능 (conda에 없는 패키지만)
pip install transformers

# 환경 목록 확인
conda env list
```

```
# 출력 예시:
# base                     /Users/you/miniconda3
# ml_project            *  /Users/you/miniconda3/envs/ml_project
```

### Conda 환경을 팀원과 공유하기

```bash
# 환경 설정을 YAML 파일로 내보내기
conda env export > environment.yml

# 다른 PC에서 동일 환경 복원
conda env create -f environment.yml
```

`environment.yml` 파일은 다음과 같은 구조입니다:

```yaml
name: ml_project
channels:
  - defaults
dependencies:
  - python=3.11
  - numpy=1.24.3
  - pandas=2.0.1
  - pip:
    - transformers==4.30.0
```

### 주의: conda와 pip 혼용 시 반드시 지킬 규칙

conda 환경에서 pip를 사용할 때는 **conda 패키지를 먼저 모두 설치한 후, pip 패키지를 마지막에 설치**하세요. 순서가 뒤바뀌면 conda가 pip로 설치한 패키지를 인식하지 못해 의존성 충돌이 발생할 수 있습니다.

## 4. Poetry — 현대적인 프로젝트 관리 도구

Poetry는 의존성 관리, 가상환경 생성, 패키지 빌드와 배포를 하나의 도구로 통합합니다. `pyproject.toml`과 `poetry.lock` 파일로 **결정적(Deterministic)** 빌드를 보장합니다.

### 실습: Poetry로 프로젝트 시작하기

```bash
# Poetry 설치
curl -sSL https://install.python-poetry.org | python3 -

# 새 프로젝트 생성 (디렉토리 구조까지 자동 생성)
poetry new my_api
cd my_api

# 또는 기존 프로젝트에서 초기화
poetry init
```

```bash
# 패키지 추가 (자동으로 의존성 해결 + lock 파일 갱신)
poetry add fastapi uvicorn

# 개발 전용 패키지는 --group dev로 분리
poetry add --group dev pytest black mypy

# 가상환경에서 명령어 실행
poetry run python main.py

# 가상환경 쉘 진입
poetry shell

# 의존성 트리 시각화
poetry show --tree
```

```
# poetry show --tree 출력 예시:
# fastapi 0.100.0
# ├── pydantic >=1.7.4
# ├── starlette >=0.27.0
# └── typing-extensions >=4.5.0
```

### Poetry vs pip+venv 비교

| 기능 | pip + venv | Poetry |
|------|-----------|--------|
| 가상환경 생성 | 수동 (`python -m venv`) | 자동 생성 |
| 의존성 해결 | 없음 (충돌 시 수동 해결) | 자동 SAT solver |
| Lock 파일 | 없음 (`freeze`로 대체) | `poetry.lock` 자동 생성 |
| 개발/프로덕션 의존성 분리 | 수동 관리 필요 | `--group dev` 옵션 |
| 패키지 빌드와 배포 | `setup.py` 별도 작성 | `poetry build && poetry publish` |
| 버전 범위 지정 | 미지원 | `^2.0`, `~2.0`, `>=2.0,<3.0` |

## 5. 실전 선택 가이드

어떤 도구를 선택할지는 프로젝트 성격에 따라 달라집니다.

**간단한 스크립트나 학습용 →** `venv`가 최고입니다. 설치할 것도 없고, Python만 있으면 바로 시작할 수 있습니다.

**데이터 사이언스 / ML 프로젝트 →** `Conda`를 추천합니다. PyTorch, TensorFlow 등 GPU 드라이버 관련 패키지 설치가 pip보다 훨씬 안정적이고 수월합니다.

**웹 서비스 / 프로덕션 배포 →** `Poetry`가 적합합니다. lock 파일로 재현 가능한 빌드를 보장하고, Docker 환경과도 궁합이 좋습니다.

```dockerfile
# Poetry + Docker 조합 예시 (프로덕션 배포)
FROM python:3.11-slim
WORKDIR /app
COPY pyproject.toml poetry.lock ./
RUN pip install poetry && \
    poetry config virtualenvs.create false && \
    poetry install --only main --no-root
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## 결론

어떤 도구를 사용하든 **"프로젝트별 가상환경 사용"**은 선택이 아닌 필수입니다. 오늘 배운 내용을 정리하면:

- **입문자:** `venv`로 시작해서 가상환경 개념을 확실히 익히세요
- **데이터 분석가:** `Miniconda`를 설치하고 `conda activate`를 습관화하세요
- **백엔드 개발자:** `Poetry`로 의존성을 엄격하게 관리하세요
- **모든 개발자:** `.gitignore`에 가상환경 폴더를 반드시 추가하고, 의존성 파일(`requirements.txt`, `poetry.lock`, `environment.yml`)은 반드시 버전 관리에 포함하세요

지금 바로 터미널을 열고 `python3 -m venv .venv`를 입력해보세요. 가상환경의 편리함을 한 번 경험하면 다시는 전역 환경에 직접 패키지를 설치하지 않게 될 것입니다.
