# Modern Java: Java 8부터 21까지의 변화

"우리 회사는 아직 Java 8인데, 굳이 업그레이드해야 하나요?" 실무에서 자주 듣는 질문입니다. 결론부터 말하면, Java 17의 Record 하나만으로도 DTO 보일러플레이트가 80% 줄어들고, Java 21의 Virtual Threads는 서버 처리량을 10배 이상 끌어올릴 수 있습니다. 이 글에서는 Java 8부터 21까지 실무에서 바로 쓸 수 있는 핵심 기능들을 코드와 함께 비교합니다.

## 1. Java 8: 함수형 프로그래밍의 시작 (2014)

Java 8은 자바 역사상 가장 큰 패러다임 전환이었습니다. 이전까지 "모든 것이 객체"였던 자바에 함수형 프로그래밍 개념이 도입되었습니다.

### Lambda Expressions

익명 클래스 대신 람다로 표현하면 코드가 극적으로 간결해집니다.

```java
// Before: 익명 클래스 (5줄)
Collections.sort(names, new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
});

// After: 람다 (1줄)
Collections.sort(names, (a, b) -> a.compareTo(b));

// 메서드 참조로 더 간결하게
Collections.sort(names, String::compareTo);
```

### Stream API 실전 활용

단순한 필터링을 넘어, 실무에서 자주 쓰는 패턴들을 살펴봅시다.

```java
List<Order> orders = getOrders();

// 패턴 1: 그룹핑 — 상태별 주문 분류
Map<OrderStatus, List<Order>> byStatus = orders.stream()
    .collect(Collectors.groupingBy(Order::getStatus));

// 패턴 2: 집계 — 총 매출 계산
long totalRevenue = orders.stream()
    .filter(o -> o.getStatus() == OrderStatus.COMPLETED)
    .mapToLong(Order::getAmount)
    .sum();

// 패턴 3: 변환 — DTO 리스트 생성
List<OrderDto> dtos = orders.stream()
    .map(o -> new OrderDto(o.getId(), o.getAmount()))
    .toList(); // Java 16+에서는 .toList() 사용 가능
```

### Optional

`null` 반환 대신 `Optional`을 사용해 NPE를 방지합니다.

```java
// 기존: null 체크 지옥
String city = null;
if (user != null && user.getAddress() != null) {
    city = user.getAddress().getCity();
}

// Optional 체이닝
String city = Optional.ofNullable(user)
    .map(User::getAddress)
    .map(Address::getCity)
    .orElse("Unknown");
```

## 2. Java 11: 안정성의 LTS (2018)

### 새로운 String 메서드

사소해 보이지만 실무에서 유틸 클래스를 줄여주는 메서드들입니다.

```java
" hello ".strip();        // "hello" (유니코드 공백도 처리)
"".isBlank();              // true (빈 문자열 + 공백만 있는 경우)
"line1\nline2".lines()     // Stream<String>으로 변환
    .forEach(System.out::println);
"ha".repeat(3);            // "hahaha"
```

### HTTP Client API

`HttpURLConnection`을 대체하는 현대적인 HTTP 클라이언트입니다.

```java
HttpClient client = HttpClient.newHttpClient();

HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/users"))
    .header("Content-Type", "application/json")
    .GET()
    .build();

// 동기 호출
HttpResponse<String> response = client.send(request,
    HttpResponse.BodyHandlers.ofString());
System.out.println(response.statusCode()); // 200
System.out.println(response.body());

// 비동기 호출
client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
    .thenApply(HttpResponse::body)
    .thenAccept(System.out::println);
```

## 3. Java 17: 생산성 혁명 (2021 LTS)

### Records — DTO의 혁명

기존에 DTO 하나 만들려면 필드, 생성자, getter, equals, hashCode, toString을 모두 작성해야 했습니다.

```java
// Before: 전통적인 DTO (약 40줄)
public class UserDto {
    private final String name;
    private final int age;

    public UserDto(String name, int age) {
        this.name = name;
        this.age = age;
    }
    public String getName() { return name; }
    public int getAge() { return age; }
    // equals, hashCode, toString 생략...
}

// After: Record (1줄)
public record UserDto(String name, int age) {}
// 생성자, getter(name(), age()), equals, hashCode, toString 자동 생성
```

Record는 불변(immutable)이므로 스레드 세이프하고, Spring의 `@RequestBody`와도 완벽히 호환됩니다.

### Sealed Classes — 타입 계층 제어

```java
// Payment 타입은 이 세 가지만 허용
public sealed interface Payment
    permits CreditCard, BankTransfer, DigitalWallet {}

public record CreditCard(String number, String cvv) implements Payment {}
public record BankTransfer(String accountNo) implements Payment {}
public record DigitalWallet(String provider) implements Payment {}

// switch에서 모든 케이스를 강제할 수 있음 (Java 21에서 완성)
```

### Pattern Matching for instanceof

```java
// Before: 캐스팅을 두 번 써야 함
if (obj instanceof String) {
    String s = (String) obj;
    System.out.println(s.length());
}

// After: 선언과 동시에 바인딩
if (obj instanceof String s) {
    System.out.println(s.length());
}
```

### Text Blocks — 여러 줄 문자열

SQL이나 JSON을 자바 코드에 넣을 때 탈출 문자 지옥에서 벗어납니다.

```java
// Before
String json = "{\n" +
    "  \"name\": \"Java\",\n" +
    "  \"version\": 17\n" +
    "}";

// After: Text Block (Java 15+)
String json = """
    {
      "name": "Java",
      "version": 17
    }
    """;
```

## 4. Java 21: 동시성의 혁명 (2023 LTS)

### Virtual Threads — 경량 스레드

기존 Platform Thread는 OS 스레드와 1:1 매핑되어 스레드 하나당 약 1MB의 메모리를 소비합니다. Virtual Thread는 JVM이 관리하는 경량 스레드로, 수백만 개를 생성해도 문제없습니다.

```java
// 기존: 10,000개 스레드 생성 → OS 자원 고갈 위험
ExecutorService old = Executors.newFixedThreadPool(200);

// Virtual Threads: 10,000개도 거뜬
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        executor.submit(() -> {
            // DB 조회 같은 블로킹 I/O 작업
            Thread.sleep(Duration.ofSeconds(1));
            return fetchFromDB();
        });
    }
}
```

Spring Boot 3.2+에서는 `spring.threads.virtual.enabled=true` 한 줄이면 모든 요청 처리에 Virtual Threads가 적용됩니다.

### Switch Pattern Matching

Sealed Classes와 결합하면 타입 안전한 분기 처리가 가능합니다.

```java
public String describe(Payment payment) {
    return switch (payment) {
        case CreditCard c   -> "카드 결제: " + c.number();
        case BankTransfer b -> "계좌 이체: " + b.accountNo();
        case DigitalWallet d -> "디지털 지갑: " + d.provider();
    }; // sealed이므로 default 불필요 — 컴파일러가 완전성 보장
}
```

### Sequenced Collections

컬렉션의 첫 번째/마지막 요소 접근이 통일되었습니다.

```java
List<String> list = List.of("A", "B", "C");
list.getFirst();    // "A" (기존: list.get(0))
list.getLast();     // "C" (기존: list.get(list.size() - 1))
list.reversed();    // ["C", "B", "A"]
```

## 버전별 핵심 기능 요약

| 버전 | 핵심 기능 | 실무 영향도 |
|---|---|---|
| Java 8 | Lambda, Stream, Optional | 코드 스타일 전환 |
| Java 11 | HTTP Client, String API, var | 유틸 의존성 감소 |
| Java 17 | Record, Sealed Classes, Pattern Matching | DTO 보일러플레이트 제거 |
| Java 21 | Virtual Threads, Switch Pattern Matching | 서버 처리량 극대화 |
