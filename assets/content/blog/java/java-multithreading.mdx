# Java 멀티스레딩과 동시성 프로그래밍: 성능의 한계를 넘어서

현대의 CPU는 대부분 멀티 코어 구조를 가지고 있습니다. 하나의 코어만 사용하는 싱글 스레드 프로그램은 하드웨어 자원을 낭비하는 것과 같습니다. 애플리케이션의 성능을 극대화하기 위해서는 멀티스레딩(Multi-threading)과 동시성(Concurrency) 프로그래밍에 대한 깊은 이해가 필수적입니다.

이 글에서는 자바에서의 스레드 생성부터 고수준의 동시성 API, 그리고 동기화 문제 해결 방법까지 다룹니다.

## 1. 프로세스와 스레드

-   **프로세스(Process):** 실행 중인 프로그램의 인스턴스로, 독립적인 메모리 공간을 가집니다.
-   **스레드(Thread):** 프로세스 내에서 실행되는 실행 단위로, 메모리(Stack 제외)를 공유합니다.

## 2. 자바에서 스레드 생성하기

### 2.1 Thread 클래스 상속
```java
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread running");
    }
}
new MyThread().start();
```

### 2.2 Runnable 인터페이스 구현 (권장)
상속은 하나만 받을 수 있으므로, 인터페이스를 구현하는 것이 유연성 측면에서 좋습니다.
```java
Runnable task = () -> System.out.println("Runnable task");
new Thread(task).start();
```

## 3. Executor Framework: 스레드 풀 관리

스레드를 매번 생성하고 소멸시키는 비용은 매우 비쌉니다. 실무에서는 `Thread`를 직접 생성하기보다 `ExecutorService`를 사용하여 스레드 풀(Thread Pool)을 관리합니다.

```java
// 고정된 크기(10개)의 스레드 풀 생성
ExecutorService executor = Executors.newFixedThreadPool(10);

for (int i = 0; i < 100; i++) {
    executor.submit(() -> {
        // 작업 수행
        System.out.println(Thread.currentThread().getName());
    });
}

executor.shutdown();
```

스레드 풀을 사용하면 작업을 큐에 쌓아두고 미리 생성된 스레드가 작업을 가져가 처리하므로 리소스 관리가 효율적입니다.

## 4. 동기화(Synchronization)와 데이터 무결성

멀티스레드 환경의 가장 큰 문제는 **공유 자원 접근**입니다. 여러 스레드가 동시에 같은 변수를 수정하면 데이터가 꼬이는 경쟁 상태(Race Condition)가 발생합니다.

### 4.1 synchronized 키워드
가장 기본적인 동기화 방법으로, 한 번에 하나의 스레드만 메서드나 블록에 접근하도록 락(Lock)을 겁니다.

```java
public synchronized void increment() {
    count++;
}
```

### 4.2 Atomic 클래스
간단한 카운터 등은 `AtomicInteger`, `AtomicLong` 등을 사용하는 것이 `synchronized`보다 성능이 훨씬 좋습니다. CAS(Compare-And-Swap) 알고리즘을 사용하여 락 없이 동기화를 보장합니다.

```java
AtomicInteger count = new AtomicInteger(0);
count.incrementAndGet();
```

### 4.3 Concurrent Collections
멀티스레드 환경에서는 `ArrayList`, `HashMap` 대신 `CopyOnWriteArrayList`, `ConcurrentHashMap`을 사용해야 안전합니다.

## 5. CompletableFuture: 비동기 프로그래밍의 정점

Java 8에서 도입된 `CompletableFuture`는 비동기 작업의 결과를 조합하고 처리하는 강력한 기능을 제공합니다. 자바스크립트의 Promise와 유사합니다.

```java
CompletableFuture.supplyAsync(() -> "Hello")
    .thenApply(s -> s + " World")
    .thenAccept(System.out::println); // "Hello World" 출력
```

## 결론

멀티스레딩은 양날의 검입니다. 잘 쓰면 성능이 비약적으로 향상되지만, 잘못 쓰면 디버깅하기 힘든 버그(Deadlock, Livelock)를 만들어냅니다. 단순히 스레드를 만드는 법을 넘어, **공유 상태를 최소화하고 불변 객체(Immutable Object)를 활용하는 설계**가 안전한 동시성 프로그래밍의 핵심입니다.
