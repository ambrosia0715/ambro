# LLM API 연동 가이드: OpenAI, Anthropic 실전 활용법

바야흐로 생성형 AI의 시대입니다. 나만의 AI 서비스를 만들고 싶다면, 거대 언어 모델(LLM)의 API를 내 애플리케이션에 연동하는 방법을 반드시 알아야 합니다. ChatGPT나 Claude 웹 인터페이스를 쓰는 것과 API를 호출하는 것은 완전히 다른 차원의 이야기입니다. API를 통해 프롬프트를 커스터마이징하고, 자체 데이터와 결합하며, 사용자에게 고유한 AI 경험을 제공할 수 있습니다.

이 글에서는 현재 가장 강력한 OpenAI(GPT-4o)와 Anthropic(Claude) API를 Python 환경에서 연동하는 전체 과정을 실습 형태로 정리합니다. 환경 설정부터 스트리밍, 에러 핸들링, 비용 최적화까지 실무에서 바로 쓸 수 있는 내용입니다.

## 1. 환경 준비: API Key 발급과 프로젝트 세팅

### 1.1 API Key 발급

각 서비스의 개발자 콘솔에서 API Key를 발급받습니다.

- **OpenAI:** platform.openai.com → API Keys 메뉴
- **Anthropic:** console.anthropic.com → API Keys 메뉴

두 서비스 모두 최초 가입 시 무료 크레딧을 제공하므로 부담 없이 실험할 수 있습니다.

### 1.2 프로젝트 세팅

Python 가상 환경을 만들고 필요한 라이브러리를 설치합니다.

```bash

mkdir llm-api-practice && cd llm-api-practice

# 가상 환경 생성 및 활성화
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
```

## 2. OpenAI API (Chat Completions)

### 2.1 기본 호출

OpenAI의 Chat Completions API는 대화형 메시지 구조를 사용합니다.

```python
from openai import OpenAI
import os

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {
            "role": "system",
            "content": "너는 Python 전문 개발자야. 간결하고 실용적인 코드를 작성해."
        },
        {
            "role": "user",
            "content": "CSV 파일을 읽어서 중복을 제거하고 정렬하는 함수를 만들어줘."
        }
    ],
    temperature=0.3,
    max_tokens=1000
)

print(response.choices[0].message.content)
print(f"토큰 사용량: {response.usage.total_tokens}")
```

### 2.2 주요 파라미터 이해

| 파라미터 | 설명 | 추천 값 |
|----------|------|---------|
| `temperature` | 0에 가까울수록 일관적, 1에 가까울수록 창의적 | 코딩: 0.1~0.3 / 글쓰기: 0.7~0.9 |
| `max_tokens` | 응답의 최대 토큰 수 | 용도에 따라 500~4000 |
| `top_p` | 누적 확률 기반 토큰 선택 | 보통 temperature와 함께 조절하지 않음 |
| `frequency_penalty` | 반복 표현 억제 (0~2) | 0.3~0.5 |

**System Prompt**는 AI의 역할과 행동 규칙을 정의하는 가장 중요한 부분입니다. 구체적일수록 답변 품질이 올라갑니다.

## 3. Anthropic API (Claude)

Claude는 특히 긴 컨텍스트 처리(200K 토큰), 논리적 추론, 지시 사항 준수 능력에서 강점을 보입니다.

### 3.1 기본 호출

```python
import anthropic
import os

client = anthropic.Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))

message = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1000,
    temperature=0.3,
    system="너는 시니어 백엔드 개발자야. 보안과 성능을 항상 고려해서 답변해.",
    messages=[
        {
            "role": "user",
            "content": "FastAPI로 JWT 인증 미들웨어를 구현해줘."
        }
    ]
)

print(message.content[0].text)
print(f"입력 토큰: {message.usage.input_tokens}")
print(f"출력 토큰: {message.usage.output_tokens}")
```

### 3.2 OpenAI와의 차이점

- `system` 메시지가 별도 파라미터로 분리되어 있습니다.
- 응답 구조가 `message.content[0].text`로 접근합니다.
- 모델명에 날짜 버전이 포함됩니다 (예: `claude-sonnet-4-20250514`).

## 4. 스트리밍 구현: 사용자 경험의 핵심

LLM 응답은 생성에 수 초가 걸립니다. 사용자가 빈 화면을 보며 기다리게 하면 안 됩니다. 한 토큰씩 실시간으로 보여주는 **스트리밍**은 프로덕션 서비스에서 필수입니다.

### 4.1 OpenAI 스트리밍

```python
stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "user", "content": "Python 데코레이터 패턴을 설명해줘."}
    ],
    stream=True
)

full_response = ""
for chunk in stream:
    content = chunk.choices[0].delta.content
    if content:
        print(content, end="", flush=True)
        full_response += content
```

### 4.2 Anthropic 스트리밍

```python
with client.messages.stream(
    model="claude-sonnet-4-20250514",
    max_tokens=1000,
    messages=[
        {"role": "user", "content": "Python 데코레이터 패턴을 설명해줘."}
    ]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
```

## 5. 에러 핸들링과 재시도 로직

프로덕션 환경에서는 네트워크 오류, Rate Limit, 서버 에러 등에 대비해야 합니다.

```python
import time
from openai import RateLimitError, APIConnectionError

def call_with_retry(client, messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            response = client.chat.completions.create(
                model="gpt-4o",
                messages=messages,
                temperature=0.3
            )
            return response.choices[0].message.content
        except RateLimitError:
            wait_time = 2 ** attempt
            print(f"Rate limit 초과. {wait_time}초 후 재시도...")
            time.sleep(wait_time)
        except APIConnectionError:
            print("연결 오류. 네트워크 상태를 확인하세요.")
            time.sleep(2)
    raise Exception("최대 재시도 횟수를 초과했습니다.")
```

핵심 포인트는 **지수 백오프(Exponential Backoff)** 전략입니다. 재시도 간격을 점점 늘려 서버에 부담을 주지 않습니다.

## 6. 비용 최적화 실전 팁

LLM API는 토큰당 과금되므로 비용 관리가 중요합니다.

### 6.1 모델 선택 전략

모든 요청에 최고 성능 모델을 쓸 필요가 없습니다. 작업 난이도에 따라 모델을 구분하세요.

```python
def choose_model(task_complexity: str) -> str:
    models = {
        "simple": "gpt-4o-mini",     # 분류, 요약, 간단한 변환
        "medium": "gpt-4o",          # 일반적인 코드 생성, 분석
        "complex": "claude-sonnet-4-20250514"  # 복잡한 추론, 긴 문서 처리
    }
    return models.get(task_complexity, "gpt-4o-mini")
```

### 6.2 비용 절약 체크리스트

- **max_tokens 제한:** 필요 이상으로 긴 응답을 받지 않도록 설정
- **프롬프트 간결화:** 불필요한 반복이나 장황한 지시를 줄이기
- **캐싱:** 동일한 질문에 대한 응답을 Redis 등에 캐싱
- **배치 처리:** OpenAI Batch API를 활용하면 50% 비용 절감 가능

## 7. 흔한 실수와 디버깅

| 증상 | 원인 | 해결법 |
|------|------|--------|
| 401 Unauthorized | API Key가 잘못되었거나 만료됨 | 콘솔에서 키 재발급 |
| 429 Rate Limit | 분당 요청 수 초과 | 재시도 로직 추가, 요청 간격 조절 |
| 응답이 잘림 | max_tokens가 너무 낮음 | 값을 늘리거나 응답 완료 여부 확인 |
| 한국어 품질 저하 | system prompt가 영어로만 작성됨 | "반드시 한국어로 답변해"를 명시 |
| 비용 폭발 | 루프에서 API를 무한 호출 | 호출 횟수 제한과 모니터링 추가 |
