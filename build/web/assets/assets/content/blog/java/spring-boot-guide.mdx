# 스프링 부트(Spring Boot) 최신 가이드: 개념, 구조, 설치 및 활용

_작성일: 2026-02-09_

새 프로젝트를 시작할 때마다 XML 설정 수십 줄을 복사하고, Tomcat을 별도로 설치하고, 의존성 버전 충돌을 해결하느라 반나절을 날려본 경험이 있으신가요? 스프링 부트(Spring Boot)는 이런 "설정 지옥"을 해결하기 위해 만들어졌습니다.

이 글에서는 스프링 부트가 해결하는 문제, 내부 동작 원리, 프로젝트 생성부터 프로파일 관리까지 실전에서 바로 쓸 수 있는 내용을 다룹니다.

![Spring Boot 개요](assets/images/blog/spring_boot_hero.webp)

## 1. 스프링 부트란? — 해결하는 3가지 문제

스프링 프레임워크는 강력하지만, 설정이 복잡하다는 치명적인 단점이 있었습니다. 스프링 부트는 이 세 가지 고통을 해결합니다.

| 기존의 고통 | 스프링 부트의 해결책 |
|---|---|
| XML/Java Config 설정이 방대함 | Auto Configuration (자동 설정) |
| 라이브러리 버전 충돌 | Starter 의존성 (검증된 조합 제공) |
| WAS(Tomcat) 별도 설치/배포 | Embedded Server (내장 서버) |

### 1.1 Auto Configuration — 클래스패스를 읽고 알아서 설정

스프링 부트는 클래스패스에 있는 라이브러리를 감지하고, 합리적인 기본 설정을 자동으로 적용합니다.

```java
// spring-boot-starter-web을 추가하면:
// → 내장 Tomcat 자동 설정
// → DispatcherServlet 자동 등록
// → Jackson(JSON 변환) 자동 설정
// → 기본 에러 핸들러 등록

// 개발자는 이 한 줄만 작성하면 됩니다
@SpringBootApplication
public class MyApp {
    public static void main(String[] args) {
        SpringApplication.run(MyApp.class, args);
    }
}
```

내부적으로 `@SpringBootApplication`은 세 가지 어노테이션의 조합입니다:

```java
@SpringBootConfiguration  // @Configuration과 동일
@EnableAutoConfiguration   // 자동 설정 활성화
@ComponentScan             // 현재 패키지 이하 빈 스캔
```

### 1.2 Starter 의존성 — 버전 관리 자동화

`spring-boot-starter-web` 하나만 추가하면 Spring MVC, Jackson, Tomcat, Validation 등 웹 개발에 필요한 의존성이 모두 포함됩니다. 버전 호환성도 스프링 부트가 보장합니다.

```gradle
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    implementation 'org.springframework.boot:spring-boot-starter-validation'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}
```

| Starter | 포함 기술 | 용도 |
|---|---|---|
| `starter-web` | MVC, Jackson, Tomcat | REST API, 웹 서버 |
| `starter-data-jpa` | Hibernate, Spring Data JPA | DB 접근 (ORM) |
| `starter-security` | Spring Security | 인증/인가 |
| `starter-webflux` | Reactor, Netty | 리액티브 웹 서버 |
| `starter-test` | JUnit 5, Mockito, AssertJ | 테스트 |

### 1.3 Embedded Server — JAR 하나로 실행

별도의 WAS 설치 없이 `java -jar app.jar`로 바로 실행됩니다. Docker 환경과도 궁합이 좋습니다.

```dockerfile
FROM eclipse-temurin:21-jre
COPY build/libs/app.jar app.jar
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## 2. 프로젝트 생성 — 실전 단계

### 2.1 Spring Initializr로 프로젝트 생성

[start.spring.io](https://start.spring.io)에서 프로젝트를 생성하거나, IntelliJ에서 직접 생성할 수 있습니다.

### 2.2 최소 구성으로 API 서버 만들기

```gradle
plugins {
    id 'java'
    id 'org.springframework.boot' version '3.3.0'
    id 'io.spring.dependency-management' version '1.1.5'
}

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}
```

```java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

@RestController
@RequestMapping("/api/health")
class HealthController {
    @GetMapping
    public Map<String, Object> health() {
        return Map.of(
            "status", "UP",
            "timestamp", Instant.now()
        );
    }
}
```

`./gradlew bootRun`을 실행하면 내장 Tomcat이 8080 포트에서 뜨고, `GET /api/health`로 응답을 확인할 수 있습니다.

## 3. 설정 관리: application.yml 마스터하기

### 3.1 기본 설정

```yaml
server:
  port: 8080
  shutdown: graceful # 종료 시 진행 중인 요청 완료 후 종료

spring:
  application:
    name: my-service
  jackson:
    property-naming-strategy: SNAKE_CASE
    default-property-inclusion: NON_NULL
```

### 3.2 프로파일로 환경 분리

개발, 스테이징, 운영 환경에서 DB URL, API 키, 로그 레벨은 달라야 합니다.

```yaml
# application.yml (공통 설정)
spring:
  profiles:
    active: local # 기본 프로파일

logging:
  level:
    root: INFO
```

```yaml
# application-local.yml (로컬 개발용)
spring:
  datasource:
    url: jdbc:h2:mem:testdb
    driver-class-name: org.h2.Driver
  h2:
    console:
      enabled: true

logging:
  level:
    com.example: DEBUG
```

```yaml
# application-prod.yml (운영용)
spring:
  datasource:
    url: jdbc:postgresql://db-host:5432/mydb
    username: ${DB_USERNAME}  # 환경 변수에서 주입
    password: ${DB_PASSWORD}

logging:
  level:
    root: WARN
```

```bash
# 운영 환경 실행 시
java -jar app.jar --spring.profiles.active=prod
```

### 3.3 @ConfigurationProperties로 타입 안전한 설정

```java
@ConfigurationProperties(prefix = "app.payment")
public record PaymentProperties(
    String apiKey,
    String secretKey,
    Duration timeout
) {}

// application.yml
// app:
//   payment:
//     api-key: your-api-key
//     secret-key: your-secret
//     timeout: 5s
```

`@Value("${app.payment.api-key}")`보다 타입 안전하고, IDE 자동완성이 되며, 검증도 가능합니다.

## 4. Actuator — 운영 가시성 확보

Actuator는 애플리케이션의 상태, 메트릭, 환경 정보를 HTTP 엔드포인트로 노출합니다.

```gradle
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
}
```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health, info, metrics, env
  endpoint:
    health:
      show-details: when-authorized # 인증된 사용자에게만 상세 표시
```

| 엔드포인트 | 용도 |
|---|---|
| `/actuator/health` | 헬스체크 (DB, 디스크, 외부 서비스 연결 상태) |
| `/actuator/metrics` | JVM 메모리, HTTP 요청 수, GC 정보 등 |
| `/actuator/env` | 현재 활성 프로파일, 설정값 확인 |
| `/actuator/info` | 빌드 정보, Git 커밋 정보 |

**보안 주의**: 운영 환경에서는 반드시 Actuator 엔드포인트에 인증을 적용하세요. 민감한 정보(DB 비밀번호, API 키)가 노출될 수 있습니다.

## 5. 자동 설정을 커스터마이즈하기

스프링 부트의 기본값이 맞지 않을 때, 원하는 부분만 오버라이드할 수 있습니다.

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    // CORS 설정 커스터마이즈
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
            .allowedOrigins("https://myapp.com")
            .allowedMethods("GET", "POST", "PUT", "DELETE");
    }

    // Jackson ObjectMapper 커스터마이즈
    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper()
            .registerModule(new JavaTimeModule())
            .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
    }
}
```

## 6. 흔한 실수와 트러블슈팅

**1. 컴포넌트 스캔 범위 실수**

`@SpringBootApplication`이 있는 클래스의 패키지 기준으로 하위만 스캔합니다. 메인 클래스를 루트 패키지에 두세요.

```
com.example          ← @SpringBootApplication 위치
com.example.service  ← 스캔됨
com.example.controller ← 스캔됨
com.other.service    ← 스캔 안됨!
```

**2. 프로파일 미설정으로 운영 DB 접속 실패**

`spring.profiles.active`를 명시하지 않으면 기본 `application.yml`만 로드됩니다. 배포 스크립트에서 프로파일 설정을 빠뜨리지 않도록 주의하세요.

**3. Graceful Shutdown 미설정**

기본적으로 스프링 부트는 즉시 종료됩니다. 진행 중인 요청이 끊기지 않도록 `server.shutdown=graceful`을 설정하세요.

## 결론

스프링 부트는 스프링의 강력한 개념(IoC/DI, AOP)을 유지하면서 설정과 배포 비용을 극적으로 줄여줍니다. 핵심 활용 전략은:

1. **Starter로 시작**하고 필요한 것만 추가하세요
2. **프로파일로 환경을 분리**하고, 민감 정보는 환경 변수로 주입하세요
3. **Actuator를 활성화**해서 운영 가시성을 확보하세요
4. 기본값으로 빠르게 시작하되, **필요한 부분만 명시적으로 커스터마이즈**하세요

처음에는 기본값으로 빠르게 만들고, 성장하면서 내부 동작을 이해해 최적화하는 것이 가장 효율적인 접근법입니다.
