
# RAG(검색 증강 생성) 전략 가이드: LLM의 한계를 넘어서

LLM(Large Language Model)은 강력하지만 두 가지 치명적인 약점이 있습니다. 첫째는 **환각(Hallucination)** 현상으로, 모르는 사실을 그럴듯하게 지어내는 것입니다. 둘째는 **지식의 최신성** 문제로, 학습 데이터 컷오프(Cut-off) 이후의 정보는 알지 못한다는 점입니다.

이 문제를 해결하기 위해 등장한 기술이 바로 **RAG(Retrieval-Augmented Generation)**입니다. 기업용 AI 서비스를 구축한다면 반드시 알아야 할 RAG의 핵심 전략을 소개합니다.

## 1. RAG의 기본 동작 원리

RAG는 시험 볼 때 '오픈북 테스트'를 하는 것과 같습니다. LLM이 머릿속에 있는 지식(학습 데이터)만으로 답하는 것이 아니라, 외부 도서관(Vector DB)에서 관련 정보를 찾아보고(Retrieval) 그 정보를 바탕으로 답을 생성(Generation)하는 방식입니다.

![RAG Architecture Diagram](assets/images/blog/rag_architecture.webp)

1.  **Ingestion:** 문서를 쪼개고(Chunking), 임베딩(Embedding)하여 벡터 DB에 저장합니다.
2.  **Retrieval:** 사용자의 질문과 가장 유사한 문서를 벡터 DB에서 검색합니다.
3.  **Generation:** 검색된 문서와 질문을 프롬프트에 넣어 LLM에게 전달하고 답변을 생성합니다.

## 2. RAG 성능을 높이는 3가지 전략

단순히 문서를 검색해서 던져주는 것만으로는 좋은 품질을 기대하기 어렵습니다. 실무에서는 다음과 같은 전략들이 사용됩니다.

### 2.1 Chunking 전략 (어떻게 쪼갤 것인가?)
문서를 너무 잘게 쪼개면 문맥이 잘리고, 너무 크게 쪼개면 불필요한 노이즈가 섞입니다.
-   **Fixed-size:** 고정된 토큰 수(예: 512, 1024)로 자릅니다. 가장 단순하지만 문맥이 끊길 수 있습니다.
-   **Recursive:** 문단, 문장 단위로 계층적으로 자릅니다. 의미 단위를 보존하는 데 유리합니다.
-   **Semantic:** 의미적 유사도가 변하는 지점을 찾아 동적으로 자릅니다. 구현은 어렵지만 품질은 가장 좋습니다.

### 2.2 Hybrid Search (어떻게 찾을 것인가?)
벡터 검색(Semantic Search)만으로는 '고유명사'나 '정확한 키워드' 검색에 약할 수 있습니다.
-   **Vector Search:** 의미적 유사성 기반 ("아이폰 배터리 문제" -> "스마트폰 전원 이슈" 문서 검색 가능)
-   **Keyword Search (BM25):** 정확한 단어 매칭 ("에러 코드 503" -> "503"이 포함된 문서 검색)
-   **Hybrid:** 두 검색 결과의 점수를 가중합(Weighted Sum)하거나 RRF(Reciprocal Rank Fusion) 알고리즘으로 재정렬하여 최적의 결과를 도출합니다.

### 2.3 Re-ranking (정확도 높이기)
벡터 DB에서 상위 50~100개의 문서를 가져온 뒤, 더 정교한(하지만 느린) Cross-Encoder 모델을 사용하여 이 문서들과 질문 간의 관련성을 다시 채점하고 순위를 매깁니다. 이 과정을 거치면 LLM에게 전달되는 문맥(Context)의 품질이 비약적으로 상승합니다.

## 3. 실무 인사이트: RAG 평가 (Evaluation)

RAG 시스템을 구축했다면 성능을 어떻게 평가해야 할까요? **RAGAS**나 **TruLens** 같은 프레임워크를 사용하면 다음 지표들을 정량적으로 측정할 수 있습니다.

-   **Faithfulness (충실성):** 답변이 검색된 문서(Context)에 기반하고 있는가? (환각 방지)
-   **Answer Relevance (답변 관련성):** 답변이 사용자 질문에 적절한가?
-   **Context Precision (문맥 정확도):** 검색된 문서가 실제로 질문과 관련이 있는가?

## 결론

RAG는 LLM을 기업의 데이터와 연결하는 가장 현실적이고 효과적인 방법입니다. 하지만 "그냥 데이터만 넣으면 되겠지"라고 생각하면 오산입니다. 데이터의 전처리(Chunking), 검색 알고리즘의 최적화(Hybrid Search), 그리고 사후 보정(Re-ranking)까지 섬세한 튜닝이 필요합니다.

성공적인 AI 서비스를 위해 오늘부터 우리 데이터에 맞는 RAG 파이프라인을 설계해보세요.
