# Google Antigravity 완전 가이드: 설치부터 실전 활용까지

_작성일: 2026-02-09_

2025년 11월 Google Developers Blog에서 공개된 **Google Antigravity**는 "에이전트가 실제로 일을 수행하는(agentic)" 흐름을 IDE에 본격적으로 녹여낸 **차세대 개발 플랫폼(퍼블릭 프리뷰)**입니다. 단순한 자동완성이나 챗봇 사이드바를 넘어서, 여러 에이전트를 동시에 띄우고 에디터, 터미널, 브라우저를 가로질러 작업을 끝까지 수행하게 만드는 것이 핵심입니다.

이 글에서는 Antigravity가 기존 AI 코딩 도구와 무엇이 다른지, 설치 및 초기 설정 방법, 그리고 실무에서 생산성을 극대화하는 활용 전략까지 체계적으로 정리합니다.

![Google Antigravity 대표 이미지](assets/images/blog/google_antigravity.webp)

## 1. Antigravity가 기존 도구와 다른 점

지금까지의 AI 코딩 도구가 "코드를 더 빨리 쓰게" 돕는 것에 가깝다면, Antigravity는 **"작업을 더 크게 위임하게"** 만드는 도구입니다. 개발자의 역할이 "구현자"에서 **오케스트레이터(지시, 검증, 피드백)**로 이동합니다.

### 1.1 아키텍처 구성

Antigravity는 세 개의 주요 Surface로 구성됩니다.

- **Editor View:** 익숙한 IDE 흐름(탭 자동완성, 인라인 명령, 코드 편집)을 유지하면서 AI 지원을 받는 공간
- **Manager Surface:** 여러 에이전트를 동시에 띄우고, 각 에이전트의 진행 상황을 관찰하며 방향을 잡아주는 관리 공간
- **Cross-surface Agents:** 에디터뿐 아니라 터미널 실행, 브라우저 검증까지 같은 맥락에서 수행하는 통합 에이전트

### 1.2 기존 도구와의 비교

| 기능 | Cursor/Copilot | Google Antigravity |
|------|----------------|-------------------|
| 코드 자동완성 | O | O |
| 멀티파일 편집 | 제한적 | 네이티브 지원 |
| 동시 멀티 에이전트 | X | O (Manager Surface) |
| 터미널 자동 실행 | 부분 지원 | 완전 통합 |
| 브라우저 자동 검증 | X | O (Browser-in-the-loop) |
| 작업 증거(Artifacts) | X | O (스크린샷, 체크리스트) |

## 2. 핵심 기능 심층 분석

### 2.1 Manager Surface: 멀티 에이전트 오케스트레이션

한 명의 개발자가 하던 일을 쪼개서 여러 에이전트에게 동시에 맡길 수 있습니다. 이것이 Antigravity의 가장 혁신적인 기능입니다.

```
# 실전 시나리오: 버그 수정을 3개 에이전트에 분담

에이전트 A에게 지시:
"이 이슈를 재현할 수 있는 최소 코드를 작성하고, 재현 과정을 스크린샷으로 남겨줘."

에이전트 B에게 지시:
"에이전트 A의 재현 결과를 참고해서 원인을 분석하고, 수정 패치를 제안해줘."

에이전트 C에게 지시:
"에이전트 B의 수정이 완료되면, 회귀 테스트를 작성하고 관련 문서를 업데이트해줘."
```

개발자는 각 에이전트의 산출물을 검토하며 방향만 잡아주면 됩니다. 순차적으로 처리하던 작업이 병렬로 진행되므로 처리 속도가 크게 단축됩니다.

### 2.2 Artifacts: 로그 대신 "증거"로 검증

에이전트가 남긴 도구 호출 로그를 전부 읽는 것은 비현실적입니다. Antigravity는 이를 대신해 **Artifacts(산출물)** 중심으로 검증하는 방식을 채택했습니다.

에이전트가 생성하는 Artifacts 유형은 다음과 같습니다.

- **작업 계획 및 체크리스트:** 수행할 단계를 명시한 문서
- **변경 요약:** 어떤 파일의 어떤 부분을 왜 변경했는지 요약
- **스크린샷 및 브라우저 녹화:** UI 변경 결과의 시각적 증거
- **테스트 실행 결과:** 자동 실행된 테스트의 통과/실패 리포트

코드 리뷰처럼 산출물에 코멘트를 남기면 에이전트가 이를 반영하여 다시 작업하는 피드백 루프가 형성됩니다.

### 2.3 Browser-in-the-Loop: 자동 브라우저 검증

웹 개발에서 "코드 변경 → 브라우저 확인" 루프를 자동화하는 기능입니다. Antigravity는 Chrome 브라우저를 직접 열고, 개발 중인 웹 페이지를 테스트하고, 스크린샷을 Artifacts로 제시합니다.

![Browser Tools 설정 화면(Enable)](assets/images/blog/antigravity_enable_browser_tools.png)

Chrome이 자동으로 감지되지 않는 환경이라면, 실행 파일 경로를 직접 지정할 수도 있습니다.

![Chrome Binary Path 설정 화면](assets/images/blog/antigravity_chrome_binary_path.png)

```
# Browser Tool 활용 프롬프트 예시
"로그인 페이지의 폼 검증 로직을 수정한 후,
브라우저에서 다음 시나리오를 테스트해줘:
1. 빈 폼 제출 시 에러 메시지 표시 확인
2. 잘못된 이메일 형식 입력 시 검증 메시지 확인
3. 정상 로그인 후 대시보드로 리다이렉트 확인
각 단계의 스크린샷을 Artifacts로 남겨줘."
```

## 3. 설치 및 초기 설정

Antigravity는 퍼블릭 프리뷰 기간 동안 개인에게 무료로 제공됩니다.

### 3.1 macOS 설치

```bash
# 방법 1: 공식 다운로드
# antigravity.google/download 에서 Apple Silicon / Intel용 DMG 다운로드
# Applications 폴더로 드래그하여 설치

# 방법 2: CLI 설치 (지원되는 경우)
# 공식 문서의 CLI 안내를 참고하세요
```

### 3.2 Windows 설치

공식 다운로드 페이지에서 x64 또는 ARM64 설치 파일을 다운로드하여 실행합니다. 설치 후 초기 설정 마법사가 안내합니다.

### 3.3 Linux 설치

공식 다운로드 페이지의 Linux 안내에 따라 배포판에 맞는 설치 방식을 선택합니다.

### 3.4 초기 설정 체크리스트

설치 후 첫 실행 시 다음 항목을 설정합니다.

```
1. Google 계정 로그인
2. 프로젝트 폴더 열기 (기존 프로젝트 추천)
3. Browser Tools 활성화 (Settings > Tools > Browser)
4. Chrome 경로 확인 (자동 감지되지 않으면 수동 설정)
5. 터미널 권한 허용 (에이전트가 명령어를 실행할 수 있도록)
6. 파일 접근 권한 설정 (필요한 범위로 최소화)
```

## 4. 실무 활용 시나리오

### 4.1 기능 단위 "끝까지 위임"

요구사항을 기능 단위로 주고, 구현부터 검증까지 포함시키면 효과가 극대화됩니다.

```
목표: 블로그 글 목록에서 'AI' 카테고리 카드 UI를 개선해줘.

조건:
- 카드당 태그 3개까지 노출, 나머지는 "+N" 형태로 표시
- 썸네일이 없는 글에는 카테고리별 기본 이미지 적용
- 호버 시 카드에 미세한 그림자 효과 추가
- 모바일에서 1열, 태블릿에서 2열, 데스크톱에서 3열 그리드

검증:
- 변경 후 브라우저에서 데스크톱/모바일 뷰 스크린샷을 Artifacts로 제공
- 기존 테스트가 모두 통과하는지 확인
```

### 4.2 유지보수 작업을 백그라운드 에이전트로

Manager Surface의 장점은 "긴 작업"을 백그라운드에서 처리할 수 있다는 것입니다.

```
# 백그라운드 에이전트에게 맡기기 좋은 작업들

1. 오래된 의존성 업데이트 + 호환성 테스트
2. ESLint/Prettier 규칙 적용 + 자동 수정
3. 테스트 커버리지가 낮은 파일에 테스트 추가
4. API 문서(Swagger/OpenAPI) 자동 생성
5. 사용하지 않는 코드/import 정리
```

본 작업(새 기능 개발)을 이어가면서, 유지보수 작업은 별도 에이전트가 병렬로 처리합니다.

### 4.3 코드 리뷰와 리팩토링

```
"@src/services/ 폴더의 모든 서비스 파일을 분석해서:
1. 중복되는 에러 핸들링 패턴을 공통 유틸로 추출
2. 하드코딩된 URL을 환경 변수로 변경
3. 변경 전후 비교를 Artifacts로 정리
4. 모든 기존 테스트가 통과하는지 확인"
```

## 5. 안전하게 사용하기: 필수 규칙

에이전트가 터미널과 파일 시스템에 접근할 수 있다는 것은 강력하지만, 실수의 비용도 큽니다. 반드시 지켜야 할 안전 규칙을 정리합니다.

### 5.1 권한 최소화 원칙

```
✅ 프로젝트 디렉토리 내 파일 읽기/쓰기만 허용
✅ npm/pip 등 패키지 매니저 명령 허용
✅ 테스트 실행 명령 허용

❌ 시스템 설정 변경 명령 차단
❌ 프로젝트 외부 경로 접근 차단
❌ 프로덕션 환경 배포 명령 차단
```

### 5.2 파괴적 명령 방지

```
# 에이전트에게 명시적으로 제한사항을 알려주세요
"주의: rm -rf, DROP TABLE 같은 파괴적 명령은 절대 실행하지 마.
대량 파일 변경 시 반드시 변경 목록을 먼저 보여주고 확인을 받아."
```

### 5.3 Git 기반 안전망

에이전트가 코드를 변경하기 전에 반드시 Git 커밋 또는 브랜치를 생성하여, 문제 발생 시 쉽게 롤백할 수 있도록 합니다.

```bash
# 에이전트 작업 전 브랜치 생성
git checkout -b agent/feature-card-ui-improvement

# 작업 완료 후 diff 확인
git diff --stat

# 문제가 있으면 롤백
git checkout main
git branch -D agent/feature-card-ui-improvement
```

## 6. Antigravity vs Cursor vs Copilot: 어떤 것을 선택할까?

| 기준 | Cursor | GitHub Copilot | Antigravity |
|------|--------|----------------|-------------|
| **강점** | 프로젝트 컨텍스트 이해 | 에코시스템 통합 | 멀티에이전트 + 브라우저 검증 |
| **적합한 팀** | 중소 규모 팀 | GitHub 중심 워크플로우 | 웹 개발 중심 팀 |
| **학습 곡선** | 낮음 (VS Code 기반) | 매우 낮음 | 중간 (새로운 개념) |
| **가격** | $20/월 (Pro) | $19/월 (Pro) | 프리뷰 기간 무료 |

팀의 워크플로우와 주력 기술 스택에 따라 선택하되, 여러 도구를 병행하는 것도 좋은 전략입니다.

## 결론: 코딩 보조를 넘어 작업 위임의 시대

Google Antigravity는 "AI가 코드를 도와준다"는 수준을 넘어 **"AI에게 작업을 위임하고 결과를 검증한다"**는 새로운 패러다임을 제시합니다. 특히 웹 개발처럼 "코드 변경 → 실행 → 브라우저 확인" 루프가 잦은 팀이라면, Browser-in-the-Loop와 Artifacts 기반 검증이 생산성에 즉각적인 영향을 줄 수 있습니다.

추천하는 첫 시작은 간단합니다. **작은 기능 하나를 "계획 + 구현 + 검증"까지 통째로 위임**해보고, 에이전트의 결과물 품질을 평가해보세요. 그 경험에서 팀에 맞는 위임 기준과 검증 루틴이 자연스럽게 만들어질 것입니다.
