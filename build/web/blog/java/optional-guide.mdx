    <h1>Java Optional 완벽 가이드</h1>
    <div class="meta">2026-01-20 &middot; 15분 &middot; Ambro</div>
    <img src="/assets/assets/images/blog/java_optional.webp" alt="Java Optional 완벽 가이드" style="width:100%;border-radius:12px;margin-bottom:2em;">
    <article><h1>Java Optional 완벽 가이드: null을 다루는 올바른 방법</h1>
<p>서비스 운영 중 가장 많이 발생하는 예외는 무엇일까요? Sentry나 Bugsnag 같은 에러 추적 도구의 통계를 보면, 거의 항상 <code>NullPointerException</code>(NPE)이 1위입니다. Tony Hoare는 null 참조를 발명한 것을 "10억 달러짜리 실수"라고 표현했습니다.</p>
<p>Java 8에서 도입된 <code>Optional<T></code>은 이 문제를 해결하기 위한 도구입니다. 하지만 잘못 사용하면 오히려 코드가 더 복잡해집니다. 이 글에서는 Optional의 올바른 사용법, 실전 패턴, 그리고 반드시 피해야 할 안티 패턴을 코드와 함께 깊이 있게 다룹니다.</p>
<h2>1. Optional이란?</h2>
<p><code>Optional<T></code>은 값이 있을 수도 있고 없을 수도 있는 컨테이너입니다. null을 직접 반환하는 대신, "결과가 없을 수 있음"을 타입 시스템으로 명시합니다.</p>
<pre><code class="language-java">
// null을 반환하는 기존 방식 — 호출자가 null 체크를 잊으면 NPE
public User findByEmail(String email) {
    return userRepository.findByEmail(email); // null 가능
}

// Optional을 반환하는 방식 — 호출자에게 "없을 수 있음"을 강제 인지
public Optional&lt;User&gt; findByEmail(String email) {
    return Optional.ofNullable(userRepository.findByEmail(email));
}
</code></pre>
<h2>2. Optional 생성: 3가지 팩토리 메서드</h2>
<pre><code class="language-java">
// 1. Optional.empty() — 비어있는 Optional
Optional&lt;String&gt; empty = Optional.empty();

// 2. Optional.of(value) — null이면 즉시 NPE 발생
Optional&lt;String&gt; present = Optional.of("Hello");
// Optional.of(null); // NPE 발생!

// 3. Optional.ofNullable(value) — null이면 empty, 아니면 값 포함
Optional&lt;String&gt; maybe = Optional.ofNullable(getUserName()); // 가장 실용적
</code></pre>
<p><strong>실무 팁</strong>: 외부 라이브러리나 레거시 코드에서 넘어온 값은 항상 <code>ofNullable()</code>로 감싸세요.</p>
<h2>3. 값 꺼내기: get()을 쓰지 마세요</h2>
<p><code>get()</code>은 값이 없으면 <code>NoSuchElementException</code>을 던집니다. 이는 NPE를 다른 예외로 바꾼 것에 불과합니다.</p>
<pre><code class="language-java">
// BAD: get()을 직접 호출 — NPE와 다를 바 없음
Optional&lt;User&gt; opt = findByEmail("test@test.com");
User user = opt.get(); // 값이 없으면 NoSuchElementException

// BAD: isPresent() + get() — Optional의 의미가 없어짐
if (opt.isPresent()) {
    User user = opt.get();
    // ...
}
</code></pre>
<p>대신 아래 메서드들을 상황에 맞게 사용하세요.</p>
<h3>3.1 orElse vs orElseGet — 차이를 반드시 알아야 합니다</h3>
<pre><code class="language-java">
// orElse: 값이 있든 없든 기본값 표현식을 항상 실행
User user = findByEmail(email).orElse(createDefaultUser());
// createDefaultUser()가 매번 호출됨! DB 저장 등 부작용이 있다면 위험

// orElseGet: 값이 없을 때만 Supplier를 실행 (Lazy Evaluation)
User user = findByEmail(email).orElseGet(() -&gt; createDefaultUser());
// 값이 있으면 createDefaultUser()는 호출되지 않음
</code></pre>
<table><thead><tr>
<th>메서드</th>
<th>기본값 생성 비용이 낮을 때</th>
<th>기본값 생성에 부작용이 있을 때</th>
</tr></thead><tbody>
<tr>
<td><code>orElse(value)</code></td>
<td>사용 가능</td>
<td>위험</td>
</tr>
<tr>
<td><code>orElseGet(supplier)</code></td>
<td>사용 가능</td>
<td>안전 (권장)</td>
</tr>
</tbody></table>
<h3>3.2 orElseThrow — 비즈니스 예외 던지기</h3>
<pre><code class="language-java">
User user = findByEmail(email)
    .orElseThrow(() -&gt; new UserNotFoundException("사용자를 찾을 수 없습니다: " + email));
</code></pre>
<p>Spring에서 REST API를 만들 때, 엔티티가 없으면 404를 반환해야 하는 경우에 자주 사용됩니다.</p>
<h3>3.3 ifPresent / ifPresentOrElse</h3>
<pre><code class="language-java">
// 값이 있을 때만 실행
findByEmail(email).ifPresent(user -&gt; sendWelcomeEmail(user));

// Java 9+: 있을 때와 없을 때를 모두 처리
findByEmail(email).ifPresentOrElse(
    user -&gt; log.info("사용자 발견: {}", user.getName()),
    ()   -&gt; log.warn("사용자 없음: {}", email)
);
</code></pre>
<h2>4. map과 flatMap: Optional의 진짜 힘</h2>
<p>Optional이 단순한 null 체크 대용이 아닌 이유는 바로 <strong>체이닝</strong>에 있습니다.</p>
<h3>4.1 map — 값 변환</h3>
<pre><code class="language-java">
// 기존의 중첩 null 체크 (Depth of Doom)
String city = "Unknown";
if (order != null) {
    Member member = order.getMember();
    if (member != null) {
        Address address = member.getAddress();
        if (address != null) {
            city = address.getCity();
        }
    }
}

// Optional의 map 체이닝 — 선언적이고 가독성 좋음
String city = Optional.ofNullable(order)
    .map(Order::getMember)
    .map(Member::getAddress)
    .map(Address::getCity)
    .orElse("Unknown");
</code></pre>
<h3>4.2 flatMap — Optional을 반환하는 메서드와 연결</h3>
<p>getter가 이미 Optional을 반환하는 경우, <code>map</code>을 쓰면 <code>Optional<Optional<T>></code>이 됩니다. <code>flatMap</code>으로 평탄화하세요.</p>
<pre><code class="language-java">
public class Member {
    private Address address;
    public Optional&lt;Address&gt; getAddress() {
        return Optional.ofNullable(address);
    }
}

// map을 쓰면: Optional&lt;Optional&lt;Address&gt;&gt; (이중 포장)
// flatMap을 쓰면: Optional&lt;Address&gt; (깔끔)
String city = Optional.ofNullable(member)
    .flatMap(Member::getAddress)
    .map(Address::getCity)
    .orElse("Unknown");
</code></pre>
<h3>4.3 filter — 조건 검증</h3>
<pre><code class="language-java">
// 18세 이상인 사용자만 처리
Optional.ofNullable(user)
    .filter(u -&gt; u.getAge() &gt;= 18)
    .ifPresent(u -&gt; grantAccess(u));
</code></pre>
<h2>5. 안티 패턴: 이렇게 쓰면 안 됩니다</h2>
<h3>5.1 필드 변수로 사용 금지</h3>
<pre><code class="language-java">
// BAD: Optional은 Serializable이 아님 → 직렬화 실패
public class User {
    private Optional&lt;String&gt; nickname; // 절대 금지!
}

// GOOD: 필드는 null 허용, getter에서 Optional 반환
public class User {
    private String nickname;
    public Optional&lt;String&gt; getNickname() {
        return Optional.ofNullable(nickname);
    }
}
</code></pre>
<h3>5.2 매개변수로 사용 금지</h3>
<pre><code class="language-java">
// BAD: 호출자에게 불필요한 래핑을 강요
public void sendEmail(Optional&lt;String&gt; email) { ... }

// GOOD: null 가능성은 @Nullable 어노테이션으로 표현
public void sendEmail(@Nullable String email) {
    if (email == null) return;
    // ...
}
</code></pre>
<h3>5.3 컬렉션을 Optional로 감싸지 마세요</h3>
<pre><code class="language-java">
// BAD: 이중 래핑 — Optional도 비어있고 List도 비어있을 수 있음
public Optional&lt;List&lt;Order&gt;&gt; findOrders(Long userId) { ... }

// GOOD: 빈 리스트 반환이 훨씬 깔끔
public List&lt;Order&gt; findOrders(Long userId) {
    List&lt;Order&gt; orders = orderRepository.findByUserId(userId);
    return orders != null ? orders : Collections.emptyList();
}
</code></pre>
<h3>5.4 기본형은 전용 Optional 사용</h3>
<pre><code class="language-java">
// BAD: 박싱/언박싱 오버헤드
Optional&lt;Integer&gt; count = Optional.of(42);

// GOOD: 전용 타입 사용
OptionalInt count = OptionalInt.of(42);
OptionalLong bigCount = OptionalLong.of(1_000_000L);
OptionalDouble ratio = OptionalDouble.of(3.14);
</code></pre>
<h2>6. Java 9+ 추가 메서드</h2>
<pre><code class="language-java">
// or() — 대체 Optional 제공 (Java 9)
Optional&lt;User&gt; user = findByEmail(email)
    .or(() -&gt; findByPhone(phone));

// stream() — Optional을 Stream으로 변환 (Java 9)
List&lt;String&gt; names = users.stream()
    .map(User::getNickname)       // Stream&lt;Optional&lt;String&gt;&gt;
    .flatMap(Optional::stream)    // Stream&lt;String&gt; (빈 Optional 제거)
    .toList();
</code></pre>
<h2>결론: Optional 사용 체크리스트</h2>
<p>Optional은 만능 도구가 아닙니다. 아래 원칙을 따르면 깔끔하게 사용할 수 있습니다.</p>
<ul>
<li><strong>반환 타입으로만</strong> 사용하세요 (필드, 매개변수, 컬렉션 래핑 금지)</li>
<li><strong><code>get()</code> 대신</strong> <code>orElse</code>, <code>orElseGet</code>, <code>orElseThrow</code>를 사용하세요</li>
<li><strong><code>orElse</code> vs <code>orElseGet</code></strong> 차이를 이해하고, 부작용이 있으면 반드시 <code>orElseGet</code> 사용</li>
<li><strong><code>map</code>/<code>flatMap</code> 체이닝</strong>으로 중첩 null 체크를 제거하세요</li>
<li><strong>기본형은</strong> <code>OptionalInt</code>, <code>OptionalLong</code>, <code>OptionalDouble</code> 사용</li>
</ul>
<p>이 원칙들을 지키면 NPE의 공포에서 벗어나 더 안전하고 읽기 쉬운 자바 코드를 작성할 수 있습니다.</p></article>
