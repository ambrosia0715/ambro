    <h1>Java 멀티스레딩과 동시성 프로그래밍</h1>
    <div class="meta">2026-01-25 &middot; 18분 &middot; Ambro</div>
    <img src="/assets/assets/images/blog/java_multithreading.webp" alt="Java 멀티스레딩과 동시성 프로그래밍" style="width:100%;border-radius:12px;margin-bottom:2em;">
    <article><h1>Java 멀티스레딩과 동시성 프로그래밍: 성능의 한계를 넘어서</h1>
<p>API 서버에 사용자가 몰리면 응답 시간이 급격히 느려집니다. 원인을 분석해보니 외부 API 호출에 3초가 걸리는데, 싱글 스레드로 순차 처리하고 있었습니다. 3개의 외부 API를 병렬로 호출하면 9초가 아닌 3초만에 끝낼 수 있습니다. 이것이 멀티스레딩의 힘입니다.</p>
<p>이 글에서는 자바의 스레드 생성부터 스레드 풀 관리, 동기화 문제 해결, 그리고 실전 비동기 프로그래밍까지 코드와 함께 단계별로 다룹니다.</p>
<h2>1. 프로세스 vs 스레드</h2>
<table><thead><tr>
<th>구분</th>
<th>프로세스(Process)</th>
<th>스레드(Thread)</th>
</tr></thead><tbody>
<tr>
<td>메모리</td>
<td>독립적인 메모리 공간</td>
<td>프로세스 내 메모리 공유 (Stack만 독립)</td>
</tr>
<tr>
<td>생성 비용</td>
<td>높음</td>
<td>상대적으로 낮음</td>
</tr>
<tr>
<td>통신 비용</td>
<td>IPC 필요 (비쌈)</td>
<td>공유 메모리로 직접 통신</td>
</tr>
<tr>
<td>장애 영향</td>
<td>다른 프로세스에 영향 없음</td>
<td>같은 프로세스의 다른 스레드에 영향</td>
</tr>
</tbody></table>
<h2>2. 스레드 생성: 3가지 방법</h2>
<h3>2.1 Thread 클래스 상속 (비권장)</h3>
<pre><code class="language-java">
class DownloadThread extends Thread {
    @Override
    public void run() {
        System.out.println(getName() + ": 파일 다운로드 중...");
    }
}

DownloadThread t = new DownloadThread();
t.start(); // run()이 아닌 start()를 호출해야 새 스레드에서 실행
</code></pre>
<p><code>start()</code> 대신 <code>run()</code>을 호출하면 새 스레드가 생성되지 않고 현재 스레드에서 실행됩니다. 초보자가 자주 실수하는 부분입니다.</p>
<h3>2.2 Runnable 인터페이스 구현 (권장)</h3>
<p>자바는 단일 상속만 지원하므로, Thread를 상속하면 다른 클래스를 상속할 수 없습니다.</p>
<pre><code class="language-java">
Runnable task = () -&gt; {
    System.out.println(Thread.currentThread().getName() + ": 작업 실행");
};

Thread t = new Thread(task, "worker-1");
t.start();
</code></pre>
<h3>2.3 Callable — 반환값이 있는 작업</h3>
<p><code>Runnable</code>은 반환값이 없고 예외도 던질 수 없습니다. 결과가 필요하면 <code>Callable</code>을 사용합니다.</p>
<pre><code class="language-java">
Callable&lt;Integer&gt; calculation = () -&gt; {
    Thread.sleep(1000);
    return 42;
};

ExecutorService executor = Executors.newSingleThreadExecutor();
Future&lt;Integer&gt; future = executor.submit(calculation);

// 결과가 준비될 때까지 블로킹
Integer result = future.get(); // 42
executor.shutdown();
</code></pre>
<h2>3. ExecutorService: 스레드 풀이 필수인 이유</h2>
<p>스레드를 매번 생성/소멸하는 비용은 비쌉니다. OS 스레드를 할당하고 해제하는 과정이 수반되기 때문입니다. 실무에서는 반드시 <strong>스레드 풀</strong>을 사용합니다.</p>
<pre><code class="language-java">
// 고정 크기 스레드 풀 (CPU 코어 수 기반)
int cores = Runtime.getRuntime().availableProcessors();
ExecutorService executor = Executors.newFixedThreadPool(cores);

List&lt;Future&lt;String&gt;&gt; futures = new ArrayList&lt;&gt;();
for (int i = 0; i &lt; 100; i++) {
    final int taskId = i;
    futures.add(executor.submit(() -&gt; {
        Thread.sleep(100);
        return "Task-" + taskId + " 완료 [" + Thread.currentThread().getName() + "]";
    }));
}

for (Future&lt;String&gt; f : futures) {
    System.out.println(f.get());
}

executor.shutdown();
</code></pre>
<h3>스레드 풀 종류 선택 가이드</h3>
<table><thead><tr>
<th>팩토리 메서드</th>
<th>특징</th>
<th>적합한 상황</th>
</tr></thead><tbody>
<tr>
<td><code>newFixedThreadPool(n)</code></td>
<td>고정 n개 스레드</td>
<td>CPU 바운드 작업</td>
</tr>
<tr>
<td><code>newCachedThreadPool()</code></td>
<td>유휴 스레드 재사용, 무제한 생성</td>
<td>짧은 I/O 작업 (주의: 폭발 가능)</td>
</tr>
<tr>
<td><code>newSingleThreadExecutor()</code></td>
<td>단일 스레드, 작업 순서 보장</td>
<td>순차 처리 필요 시</td>
</tr>
<tr>
<td><code>newScheduledThreadPool(n)</code></td>
<td>주기적/지연 실행 지원</td>
<td>배치 스케줄링</td>
</tr>
<tr>
<td><code>newVirtualThreadPerTaskExecutor()</code></td>
<td>Java 21+ 가상 스레드</td>
<td>I/O 바운드 대량 작업</td>
</tr>
</tbody></table>
<p><strong>주의</strong>: <code>newCachedThreadPool()</code>은 스레드 수 제한이 없어서 요청이 폭증하면 OOM이 발생할 수 있습니다. 운영 환경에서는 <code>ThreadPoolExecutor</code>를 직접 생성해 최대 스레드 수를 제한하세요.</p>
<h2>4. 동기화(Synchronization): 공유 자원의 위험</h2>
<p>멀티스레드 환경에서 가장 위험한 것은 <strong>경쟁 상태(Race Condition)</strong>입니다.</p>
<pre><code class="language-java">
// 위험한 코드: 여러 스레드가 동시에 count++를 실행
public class UnsafeCounter {
    private int count = 0;

    public void increment() {
        count++; // read → modify → write (3단계, 원자적이지 않음)
    }

    public int getCount() { return count; }
}

// 테스트: 1000개 스레드가 각각 1000번 증가 → 기대값 1,000,000
UnsafeCounter counter = new UnsafeCounter();
ExecutorService executor = Executors.newFixedThreadPool(10);

for (int i = 0; i &lt; 1000; i++) {
    executor.submit(() -&gt; {
        for (int j = 0; j &lt; 1000; j++) counter.increment();
    });
}
executor.shutdown();
executor.awaitTermination(10, TimeUnit.SECONDS);
System.out.println(counter.getCount()); // 1,000,000이 아닌 더 작은 값!
</code></pre>
<h3>4.1 synchronized 키워드</h3>
<p>가장 기본적인 동기화 방법입니다. 한 번에 하나의 스레드만 접근할 수 있도록 락을 겁니다.</p>
<pre><code class="language-java">
public class SyncCounter {
    private int count = 0;

    public synchronized void increment() {
        count++; // 한 번에 하나의 스레드만 실행
    }

    public synchronized int getCount() { return count; }
}
</code></pre>
<p>단점: 모든 스레드가 락을 기다리므로 성능이 저하됩니다.</p>
<h3>4.2 AtomicInteger — 락 없는 동기화</h3>
<p>CAS(Compare-And-Swap) 알고리즘으로 락 없이 원자적 연산을 보장합니다. 단순 카운터에는 <code>synchronized</code>보다 훨씬 빠릅니다.</p>
<pre><code class="language-java">
public class AtomicCounter {
    private final AtomicInteger count = new AtomicInteger(0);

    public void increment() {
        count.incrementAndGet(); // 원자적 연산
    }

    public int getCount() { return count.get(); }
}
</code></pre>
<h3>4.3 Concurrent Collections</h3>
<p><code>HashMap</code>, <code>ArrayList</code>는 멀티스레드에서 안전하지 않습니다. 대신 전용 컬렉션을 사용하세요.</p>
<pre><code class="language-java">
// BAD: 멀티스레드에서 ConcurrentModificationException 또는 데이터 손실
Map&lt;String, Integer&gt; map = new HashMap&lt;&gt;();

// GOOD: 세그먼트 기반 락으로 높은 동시성 보장
ConcurrentMap&lt;String, Integer&gt; safeMap = new ConcurrentHashMap&lt;&gt;();
safeMap.put("count", 1);
safeMap.computeIfAbsent("visits", key -&gt; 0);
</code></pre>

<th>비안전 컬렉션</th>
<th>스레드 안전 대안</th>
</tr></thead><tbody>

<td><code>HashMap</code></td>
<td><code>ConcurrentHashMap</code></td>
</tr>
<tr>
<td><code>ArrayList</code></td>

</tr>

<td><code>LinkedList</code> (Queue)</td>

</tr>

<h2>5. CompletableFuture: 비동기 프로그래밍의 정점</h2>
<p>Java 8의 <code>CompletableFuture</code>는 비동기 작업을 체이닝하고 조합하는 강력한 API입니다.</p>
<h3>5.1 기본 사용법</h3>
<pre><code class="language-java">
CompletableFuture&lt;String&gt; future = CompletableFuture
    .supplyAsync(() -&gt; fetchUserFromDB(userId))    // 비동기 DB 조회
    .thenApply(user -&gt; user.getName())              // 결과 변환
    .thenApply(name -&gt; "안녕하세요, " + name)       // 추가 변환
    .exceptionally(ex -&gt; "사용자 조회 실패");       // 에러 처리
</code></pre>
<h3>5.2 실전: 여러 API를 병렬로 호출</h3>
<pre><code class="language-java">
// 3개의 외부 API를 동시에 호출 → 가장 느린 것 기준으로 완료
CompletableFuture&lt;UserProfile&gt; profileFuture =
    CompletableFuture.supplyAsync(() -&gt; fetchProfile(userId));
CompletableFuture&lt;List&lt;Order&gt;&gt; ordersFuture =
    CompletableFuture.supplyAsync(() -&gt; fetchOrders(userId));
CompletableFuture&lt;Integer&gt; pointsFuture =
    CompletableFuture.supplyAsync(() -&gt; fetchPoints(userId));

// 세 결과를 조합
CompletableFuture.allOf(profileFuture, ordersFuture, pointsFuture)
    .thenRun(() -&gt; {
        UserProfile profile = profileFuture.join();
        List&lt;Order&gt; orders = ordersFuture.join();
        int points = pointsFuture.join();
        return new UserDashboard(profile, orders, points);
    });
</code></pre>
<p>순차 실행 시 각각 1초, 2초, 1초면 총 4초가 걸리지만, 병렬 실행하면 2초(가장 느린 것)만에 끝납니다.</p>
<h2>6. Deadlock 방지 전략</h2>
<p>두 스레드가 서로의 락을 기다리며 영원히 블로킹되는 현상입니다.</p>
<pre><code class="language-java">
// Deadlock 발생 가능 코드
Object lockA = new Object();
Object lockB = new Object();

// Thread 1: lockA → lockB 순서
// Thread 2: lockB → lockA 순서 (역순!)
</code></pre>
<p><strong>방지 원칙</strong>:</p>
<ul>
<li>락 획득 순서를 전체 애플리케이션에서 통일하세요</li>
<li><code>tryLock()</code>으로 타임아웃을 설정하세요</li>
<li>가능하면 락을 사용하지 말고, <code>Atomic</code> 클래스나 불변 객체를 활용하세요</li>
</ul>
<h2>결론: 안전한 동시성 프로그래밍 원칙</h2>
<ul>
<li><strong>스레드를 직접 생성하지 마세요</strong> — 항상 <code>ExecutorService</code>(스레드 풀)를 사용하세요</li>
<li><strong>공유 상태를 최소화하세요</strong> — 불변 객체(<code>record</code>, <code>final</code>)를 우선하세요</li>
<li><strong>단순 카운터는 <code>AtomicInteger</code></strong>, 복잡한 동기화는 <code>synchronized</code> 또는 <code>ReentrantLock</code>을 사용하세요</li>
<li><strong>비동기 조합은 <code>CompletableFuture</code></strong>로 선언적으로 표현하세요</li>
<li><strong>Java 21 이상이라면 Virtual Threads</strong>를 적극 활용하세요</li>
</ul>
