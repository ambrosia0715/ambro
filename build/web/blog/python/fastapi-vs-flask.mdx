    <article><h1>FastAPI vs Flask: 모던 파이썬 웹 프레임워크 실전 비교</h1>
<p>새 프로젝트를 시작하려는데 팀에서 논쟁이 벌어집니다. "Flask로 빠르게 만들자" vs "FastAPI로 제대로 만들자". 이 글에서 동일한 기능을 두 프레임워크로 직접 구현하면서 차이점을 체감해봅시다.</p>
<h2>1. 프레임워크 한눈에 비교</h2>
<p>본격적인 코드에 앞서, 두 프레임워크의 핵심 특성을 비교합니다.</p>
<table><thead><tr>
<th>항목</th>
<th>Flask</th>
<th>FastAPI</th>
</tr></thead><tbody>
<tr>
<td>첫 릴리스</td>
<td>2010년</td>
<td>2018년</td>
</tr>
<tr>
<td>비동기 지원</td>
<td>제한적 (2.0부터 부분 지원)</td>
<td>네이티브 async/await</td>
</tr>
<tr>
<td>데이터 검증</td>

<td>Pydantic 내장</td>
</tr>
<tr>
<td>API 문서 자동 생성</td>

<h2>2. 환경 설정</h2>
<p>두 프레임워크를 모두 설치하고 같은 기능을 구현해봅시다.</p>
<pre><code class="language-bash">
# Flask 설치
pip install flask

# FastAPI + ASGI 서버 설치
pip install fastapi uvicorn
</code></pre>
<h2>3. Hello World 비교</h2>
<h3>Flask</h3>
<pre><code class="language-python">
# app_flask.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def hello():
    return {"message": "Hello from Flask!"}

if __name__ == "__main__":
    app.run(debug=True, port=5000)
</code></pre>
<pre><code class="language-bash">
python app_flask.py
# → http://127.0.0.1:5000 에서 확인
</code></pre>
<h3>FastAPI</h3>
<pre><code class="language-python">
# app_fastapi.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
async def hello():
    return {"message": "Hello from FastAPI!"}
</code></pre>
<pre><code class="language-bash">
uvicorn app_fastapi:app --reload --port=8000
# → http://127.0.0.1:8000 에서 확인
# → http://127.0.0.1:8000/docs 에서 Swagger UI 자동 생성!
</code></pre>
<p>FastAPI는 코드를 작성하는 것만으로 <code>/docs</code> 경로에 대화형 API 문서가 자동 생성됩니다. 프론트엔드 개발자와 협업할 때 별도의 API 문서를 작성할 필요가 없습니다.</p>
<h2>4. CRUD API 구현 비교</h2>
<p>실무에서 가장 흔한 CRUD(Create, Read, Update, Delete) API를 구현하면서 차이를 비교합니다. 간단한 할 일(Todo) 관리 API를 만들어봅시다.</p>
<h3>Flask로 구현</h3>
<pre><code class="language-python">
# flask_todo.py
from flask import Flask, request, jsonify

app = Flask(__name__)

todos = []
next_id = 1

@app.route("/todos", methods=["GET"])
def get_todos():
    return jsonify(todos)

@app.route("/todos", methods=["POST"])
def create_todo():
    global next_id
    data = request.get_json()

    # 수동으로 데이터 검증해야 함
    if not data or "title" not in data:
        return jsonify({"error": "title 필드는 필수입니다"}), 400
    if not isinstance(data["title"], str):
        return jsonify({"error": "title은 문자열이어야 합니다"}), 400

    todo = {
        "id": next_id,
        "title": data["title"],
        "completed": data.get("completed", False)
    }
    todos.append(todo)
    next_id += 1
    return jsonify(todo), 201

@app.route("/todos/&lt;int:todo_id&gt;", methods=["PUT"])
def update_todo(todo_id):
    data = request.get_json()
    for todo in todos:
        if todo["id"] == todo_id:
            todo["title"] = data.get("title", todo["title"])
            todo["completed"] = data.get("completed", todo["completed"])
            return jsonify(todo)
    return jsonify({"error": "Todo를 찾을 수 없습니다"}), 404

@app.route("/todos/&lt;int:todo_id&gt;", methods=["DELETE"])
def delete_todo(todo_id):
    global todos
    before = len(todos)
    todos = [t for t in todos if t["id"] != todo_id]
    if len(todos) == before:
        return jsonify({"error": "Todo를 찾을 수 없습니다"}), 404
    return "", 204
</code></pre>
<h3>FastAPI로 구현</h3>
<pre><code class="language-python">
# fastapi_todo.py
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from typing import Optional

app = FastAPI(title="Todo API", version="1.0.0")

class TodoCreate(BaseModel):
    title: str
    completed: bool = False

class TodoUpdate(BaseModel):
    title: Optional[str] = None
    completed: Optional[bool] = None

class TodoResponse(BaseModel):
    id: int
    title: str
    completed: bool

todos: list[dict] = []
next_id = 1

@app.get("/todos", response_model=list[TodoResponse])
async def get_todos():
    return todos

@app.post("/todos", response_model=TodoResponse, status_code=201)
async def create_todo(todo: TodoCreate):
    global next_id
    new_todo = {"id": next_id, **todo.model_dump()}
    todos.append(new_todo)
    next_id += 1
    return new_todo

@app.put("/todos/{todo_id}", response_model=TodoResponse)
async def update_todo(todo_id: int, todo_update: TodoUpdate):
    for todo in todos:
        if todo["id"] == todo_id:
            update_data = todo_update.model_dump(exclude_unset=True)
            todo.update(update_data)
            return todo
    raise HTTPException(status_code=404, detail="Todo를 찾을 수 없습니다")

@app.delete("/todos/{todo_id}", status_code=204)
async def delete_todo(todo_id: int):
    global todos
    before = len(todos)
    todos = [t for t in todos if t["id"] != todo_id]
    if len(todos) == before:
        raise HTTPException(status_code=404, detail="Todo를 찾을 수 없습니다")
</code></pre>
<h3>핵심 차이점 분석</h3>
<table><thead><tr>
<th>비교 포인트</th>
<th>Flask</th>
<th>FastAPI</th>
</tr></thead><tbody>
<tr>
<td>데이터 검증</td>
<td><code>if "title" not in data</code> 수동 작성</td>
<td><code>Pydantic BaseModel</code>에서 자동 처리</td>
</tr>
<tr>
<td>타입 변환</td>
<td><code>request.get_json()</code> → dict 수동 파싱</td>
<td>함수 인자로 자동 파싱 및 타입 변환</td>
</tr>
<tr>
<td>에러 응답</td>
<td>직접 JSON 구성</td>
<td>422 Validation Error 자동 반환</td>
</tr>
<tr>
<td>API 문서</td>
<td>별도 작성 필요</td>
<td><code>/docs</code>에서 자동 제공</td>
</tr>
<tr>
<td>응답 직렬화</td>
<td><code>jsonify()</code> 수동 호출</td>
<td><code>response_model</code>로 자동 처리</td>
</tr>
</tbody></table>
<p>FastAPI에서 잘못된 데이터를 보내면 이런 응답이 자동으로 반환됩니다:</p>
<pre><code class="language-json">
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "title"],
      "msg": "Field required",
      "input": {}
    }
  ]
}
</code></pre>
<p>검증 코드를 한 줄도 작성하지 않았는데 Pydantic이 알아서 처리합니다.</p>
<h2>5. 비동기 성능 차이 체감하기</h2>
<p>외부 API를 호출하는 엔드포인트에서 비동기의 차이가 극명하게 드러납니다.</p>
<pre><code class="language-python">
# FastAPI: 비동기로 여러 외부 서비스 동시 호출
import httpx
import asyncio
from fastapi import FastAPI

app = FastAPI()

@app.get("/dashboard")
async def get_dashboard():
    async with httpx.AsyncClient() as client:
        user_task = client.get("https://api.example.com/user")
        orders_task = client.get("https://api.example.com/orders")
        stats_task = client.get("https://api.example.com/stats")

        user, orders, stats = await asyncio.gather(
            user_task, orders_task, stats_task
        )

    return {
        "user": user.json(),
        "orders": orders.json(),
        "stats": stats.json()
    }
</code></pre>
<p>세 API 호출이 동시에 실행되므로, 가장 느린 호출 시간만큼만 걸립니다. Flask의 동기 방식이었다면 세 호출의 시간이 합산됩니다.</p>
<h2>6. 흔한 실수와 트러블슈팅</h2>
<h3>FastAPI에서 흔한 실수</h3>
<pre><code class="language-python">
# 실수 1: 경로 순서 문제
@app.get("/users/{user_id}")  # 이게 먼저 매칭됨
async def get_user(user_id: str): ...

@app.get("/users/me")  # 여기 도달 불가! "me"가 user_id로 매칭
async def get_current_user(): ...

# 해결: 구체적인 경로를 먼저 선언
@app.get("/users/me")
async def get_current_user(): ...

@app.get("/users/{user_id}")
async def get_user(user_id: str): ...

# 실수 2: async 빠뜨리고 await 사용 → SyntaxError
# 실수 3: Flask의 request.json 대신 Pydantic 모델을 사용해야 함
</code></pre>
<h2>7. 선택 가이드: 어떤 상황에서 무엇을 쓸까?</h2>
<p><strong>FastAPI를 선택하세요:</strong></p>
<ul>
<li>RESTful API 서버 또는 마이크로서비스를 구축할 때</li>
<li>비동기 I/O가 필요한 고성능 서비스를 만들 때</li>
<li>프론트엔드 팀과 API 스펙 공유가 중요할 때</li>
<li>타입 안전성과 자동 검증이 필요할 때</li>
</ul>
<p><strong>Flask를 선택하세요:</strong></p>
<ul>
<li>Jinja2 템플릿으로 HTML을 렌더링하는 전통적인 웹사이트를 만들 때</li>
<li>빠른 프로토타입이 필요하고 팀이 Flask에 익숙할 때</li>
<li>기존 Flask 기반 프로젝트를 유지보수할 때</li>
</ul>
<h2>결론</h2>
<p>Flask는 10년 넘게 검증된 훌륭한 프레임워크입니다. 하지만 <strong>새로운 API 서버를 만든다면 FastAPI가 거의 모든 면에서 우위</strong>에 있습니다. 자동 문서화, 타입 기반 검증, 네이티브 비동기 지원은 개발 생산성과 코드 품질을 동시에 끌어올립니다.</p>
<p>핵심 정리:</p>
<ul>
<li>FastAPI는 <strong>성능 3~4배</strong>, <strong>코드량 30~40% 절감</strong>, <strong>API 문서 자동 생성</strong></li>
<li>Flask는 <strong>HTML 렌더링 웹사이트</strong>와 <strong>레거시 유지보수</strong>에 여전히 강점</li>
</ul>
<p>지금 바로 <code>pip install fastapi uvicorn</code>을 실행하고, <code>/docs</code>에서 Swagger UI를 확인해보세요.</p></article>
