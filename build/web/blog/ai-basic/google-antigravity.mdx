    <h1>Google Antigravity 최신 가이드</h1>
    <div class="meta">2026-02-09 &middot; 11분 &middot; Ambro</div>
    <img src="/assets/assets/images/blog/google_antigravity.webp" alt="Google Antigravity 최신 가이드" style="width:100%;border-radius:12px;margin-bottom:2em;">
    <article><h1>Google Antigravity 최신 가이드: 기능, 설치, 활용까지 한 번에</h1>
<p><em>작성일: 2026-02-09</em></p>
<p>2025년 11월 Google Developers Blog에서 공개된 <strong>Google Antigravity</strong>는 “에이전트가 실제로 일을 수행하는(agentic)” 흐름을 IDE에 본격적으로 녹여낸 <strong>차세대 개발 플랫폼(퍼블릭 프리뷰)</strong>입니다. 단순한 자동완성이나 챗봇 사이드바를 넘어서, <strong>여러 에이전트를 동시에 띄우고(Manager surface) 에디터·터미널·브라우저를 가로질러 작업을 끝까지 수행</strong>하게 만드는 것이 핵심이에요.</p>
<img src="/assets/assets/images/blog/google_antigravity.webp" alt="Google Antigravity 대표 이미지" loading="lazy" style="max-width:100%;height:auto;border-radius:8px;margin:1em 0;">
<h2>1) Antigravity가 ‘AI Dev’에 중요한 이유</h2>
<p>지금까지의 AI 코딩 도구가 “코드를 더 빨리 쓰게” 돕는 것에 가깝다면, Antigravity는 “작업을 더 크게 위임하게” 만드는 쪽에 가깝습니다.</p>
<ul>
<li><strong>Editor View</strong>: 익숙한 IDE 흐름(탭 자동완성, 자연어 명령, 코드 편집)을 유지</li>
<li><strong>Manager Surface</strong>: 에이전트를 여러 개 띄우고, 비동기적으로(백그라운드) 작업을 진행/관찰</li>
<li><strong>Cross-surface Agents</strong>: 에디터뿐 아니라 <strong>터미널 실행, 브라우저 검증</strong>까지 같은 맥락에서 수행</li>
</ul>
<p>즉, 개발자의 역할이 “구현자”에서 <strong>오케스트레이터(지시·검증·피드백)</strong>로 이동하기 쉬운 구조입니다.</p>
<h2>2) 핵심 기능: 무엇이 ‘새로운가’</h2>
<h3>(1) Manager Surface로 “멀티 에이전트”를 관리</h3>
<p>한 명의 개발자가 하던 일을 쪼개서 여러 에이전트에게 동시에 맡길 수 있습니다. 예를 들면:</p>
<ul>
<li>A 에이전트: 버그 재현 + 최소 재현 코드 작성</li>
<li>B 에이전트: 원인 분석 + 수정안 제안</li>
<li>C 에이전트: 회귀 테스트 추가 + 문서 업데이트</li>
</ul>
<p>개발자는 결과물을 한 번에 검토하면서 방향만 잡아주면 됩니다.</p>
<h3>(2) Artifacts 기반 검증(로그 대신 “증거”)</h3>
<p>에이전트가 남긴 도구 호출 로그를 끝까지 읽는 건 피곤합니다. Antigravity는 이를 대신해 <strong>Artifacts(산출물)</strong> 중심으로 검증하게 설계되었습니다.</p>
<ul>
<li>작업 계획/체크리스트</li>
<li>변경 요약</li>
<li>스크린샷/브라우저 녹화(검증 증거)</li>
</ul>
<p>코드 리뷰처럼 산출물에 코멘트를 남기면 에이전트가 반영하는 식의 피드백 루프도 강조됩니다.</p>
<h3>(3) 브라우저 도구: “브라우저-인-더-루프” 검증</h3>
<p>문서에 따르면 Antigravity는 Chrome 브라우저를 열고 읽고 제어하여 <strong>개발 중인 웹 페이지를 테스트/검증</strong>할 수 있습니다. 별도의 브라우저 프로필을 사용해 일상 브라우징과 분리하며, 스크린샷/녹화 등을 Artifacts로 제시합니다.</p>
<p>아래는 공식 문서에 나온 설정 화면 예시입니다.</p>
<img src="/assets/assets/images/blog/antigravity_enable_browser_tools.png" alt="Browser Tools 설정 화면(Enable)" loading="lazy" style="max-width:100%;height:auto;border-radius:8px;margin:1em 0;">
<p>Chrome이 자동으로 감지되지 않는 환경이라면, 실행 파일 경로를 직접 지정할 수도 있습니다.</p>
<img src="/assets/assets/images/blog/antigravity_chrome_binary_path.png" alt="Chrome Binary Path 설정 화면" loading="lazy" style="max-width:100%;height:auto;border-radius:8px;margin:1em 0;">
<h2>3) 설치 방법(공식 다운로드 기준)</h2>
<p>Antigravity는 퍼블릭 프리뷰 기간 동안 개인에게 무료로 제공되며, Windows/macOS/Linux 다운로드를 제공합니다.</p>
<h3>macOS</h3>
<ul>
<li>공식 다운로드 페이지에서 Apple Silicon / Intel 용 DMG를 다운로드합니다.</li>
<li>앱을 Applications로 이동해 실행합니다.</li>
<li>최초 실행 시 <strong>권한(파일/네트워크)</strong> 요청이 나오면 개발 작업에 필요한 범위로 허용합니다.</li>
</ul>
<h3>Windows</h3>
<ul>
<li>공식 다운로드 페이지에서 x64 또는 ARM64 설치 파일을 다운로드합니다.</li>
<li>설치 후 실행하여 초기 설정을 진행합니다.</li>
</ul>
<h3>Linux</h3>
<p>공식 다운로드 페이지의 Linux 안내에 따라 배포판에 맞는 설치 방식을 선택합니다.</p>
<blockquote><p>설치 링크: <code>antigravity.google/download</code></p></blockquote>
<h2>4) 실무 활용법: “어떻게 쓰면 좋은가”</h2>
<h3>(1) 기능 단위로 “끝까지 위임”하기</h3>
<p>다음처럼 요구사항을 기능 단위로 주고, 검증까지 포함시키면 효과가 큽니다.</p>
<pre><code class="language-text">
목표: 블로그 글 목록에서 'AI Dev' 카테고리 카드 UI를 개선해줘.
조건:
- 카드당 태그 3개까지 노출
- 썸네일이 없으면 기본 이미지
- 변경 후 브라우저에서 렌더링 스크린샷(Artifacts)로 검증 결과 제공
</code></pre>
<h3>(2) 유지보수/정리 작업은 백그라운드 에이전트로</h3>
<ul>
<li>오래된 코드/의존성 정리</li>
<li>파일/폴더 구조 정리</li>
<li>테스트 추가, 문서 최신화</li>
</ul>
<p>같은 “긴 작업”은 Manager Surface에 던져두고, 본 작업을 이어가는 방식이 좋습니다.</p>
<h3>(3) 안전하게 쓰는 규칙(중요)</h3>
<p>에이전트가 터미널과 파일에 접근할 수 있다는 건 강력하지만, 그만큼 실수의 비용도 큽니다.</p>
<ul>
<li><strong>파괴적 명령(삭제/대량 변경)</strong>은 반드시 확인 단계 포함</li>
<li>권한은 필요한 범위로 최소화</li>
<li>Artifacts(스크린샷/변경 요약)로 <strong>검증 루틴</strong> 만들기</li>
</ul>
<h2>결론</h2>
<p>Google Antigravity는 “코딩 보조”를 넘어 <strong>작업 위임과 검증의 자동화</strong>를 전면에 둔 IDE/플랫폼입니다. 특히 웹 개발처럼 “코드 변경 → 실행 → 브라우저 확인” 루프가 잦은 팀이라면, 브라우저-인-더-루프와 Artifacts 기반 검증이 생산성에 바로 영향을 줄 수 있어요.</p>
<p>AI Dev 관점에서 추천하는 첫 시작은 간단합니다. <strong>작은 기능 하나를 ‘계획+구현+검증’까지 통째로 위임</strong>해 보고, 팀/개인에게 맞는 검증 기준을 정해보세요.</p></article>
