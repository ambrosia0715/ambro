    <h1>AI를 활용한 코드 리뷰 자동화</h1>
    <div class="meta">2026-02-06 &middot; 18분 &middot; Ambro</div>
    <img src="/assets/assets/images/blog/ai_code_review.webp" alt="AI를 활용한 코드 리뷰 자동화" style="width:100%;border-radius:12px;margin-bottom:2em;">
    <article><h1>AI를 활용한 코드 리뷰 자동화 시스템 구축 가이드</h1>
<p>코드 리뷰는 소프트웨어 품질을 유지하는 가장 중요한 활동이지만, 바쁜 개발팀에게는 큰 부담입니다. "오타 수정해주세요", "변수명 컨벤션이 다릅니다", "이 부분 null 체크가 빠져있네요" 같은 기계적인 지적에 시간을 쓰다 보면, 정작 중요한 아키텍처나 비즈니스 로직 검토에는 에너지가 남지 않습니다.</p>
<p>이러한 단순 반복 리뷰는 AI에게 맡기고, 사람은 고차원적인 판단에 집중할 수 있도록 <strong>AI 코드 리뷰 자동화 시스템</strong>을 처음부터 끝까지 구축하는 방법을 소개합니다. GitHub Actions와 OpenAI API를 결합하여, PR이 올라올 때마다 자동으로 코드를 분석하고 피드백을 남기는 봇을 만들어보겠습니다.</p>
<h2>1. 시스템 아키텍처 설계</h2>
<p>전체 흐름은 다음과 같습니다.</p>
<pre><code class="language-">
PR 생성/수정 → GitHub Actions 트리거 → 변경 코드(diff) 추출
→ LLM에 코드 + 리뷰 가이드라인 전송 → 분석 결과를 PR 코멘트로 등록
</code></pre>
<p>이 시스템의 구성 요소는 세 가지입니다.</p>
<ul>
<li><strong>트리거:</strong> GitHub Actions (PR 이벤트 감지)</li>
<li><strong>분석 엔진:</strong> Python 스크립트 + OpenAI API</li>
<li><strong>출력:</strong> GitHub API를 통한 PR 코멘트 자동 등록</li>
</ul>
<h2>2. GitHub Actions 워크플로우 설정</h2>
<p>프로젝트 루트에 <code>.github/workflows/ai-review.yml</code> 파일을 생성합니다.</p>
<pre><code class="language-yaml">
name: AI Code Review

on:
  pull_request:
    types: [opened, synchronize]

permissions:
  contents: read
  pull-requests: write

jobs:
  ai-review:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: pip install openai PyGithub

      - name: Run AI Reviewer
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          PR_NUMBER: ${{ github.event.pull_request.number }}
          REPO_NAME: ${{ github.repository }}
        run: python scripts/ai_reviewer.py
</code></pre>
<p><code>fetch-depth: 0</code>은 전체 git 히스토리를 가져와 diff를 정확하게 추출하기 위함입니다. <code>GITHUB_TOKEN</code>은 GitHub Actions에서 자동으로 제공되므로 별도 설정이 필요 없습니다.</p>
<h2>3. AI 리뷰어 스크립트 작성</h2>
<p><code>scripts/ai_reviewer.py</code> 파일을 생성합니다.</p>
<h3>3.1 변경 코드 추출</h3>
<p>전체 코드를 LLM에 보내면 토큰 비용이 폭발합니다. PR에서 변경된 부분만 추출하여 전송합니다.</p>
<pre><code class="language-python">
import subprocess
import os
from github import Github
from openai import OpenAI

def get_pr_diff():
    """PR의 변경 사항(diff)을 추출합니다."""
    result = subprocess.run(
        ["git", "diff", "origin/main...HEAD", "--unified=5"],
        capture_output=True, text=True
    )
    return result.stdout

def split_diff_by_file(diff_text: str) -&gt; dict[str, str]:
    """diff를 파일별로 분리합니다."""
    files = {}
    current_file = None
    current_content = []

    for line in diff_text.split("\n"):
        if line.startswith("diff --git"):
            if current_file:
                files[current_file] = "\n".join(current_content)
            parts = line.split(" b/")
            current_file = parts[-1] if len(parts) &gt; 1 else "unknown"
            current_content = [line]
        else:
            current_content.append(line)

    if current_file:
        files[current_file] = "\n".join(current_content)
    return files
</code></pre>
<h3>3.2 프롬프트 엔지니어링</h3>
<p>AI에게 "리뷰해줘"라고 하면 "좋아 보입니다" 같은 무의미한 답변을 받게 됩니다. 구체적인 페르소나와 분석 기준을 제공해야 합니다.</p>
<pre><code class="language-python">
SYSTEM_PROMPT = """당신은 10년 경력의 시니어 소프트웨어 엔지니어입니다.
다음 기준으로 코드를 분석하고, 문제가 발견된 경우에만 피드백하세요.

## 분석 기준
1. 버그/런타임 에러 가능성 (null 참조, 인덱스 초과, 타입 오류 등)
2. 보안 취약점 (SQL 인젝션, XSS, 하드코딩된 시크릿 등)
3. 성능 문제 (불필요한 루프, N+1 쿼리, 메모리 누수 등)
4. 에러 핸들링 누락
5. 명백한 코딩 컨벤션 위반

## 답변 형식 (JSON 배열)
[
  {
    "file": "파일 경로",
    "line": 라인 번호 (대략적),
    "severity": "critical | warning | suggestion",
    "issue": "문제 설명 (한 줄)",
    "suggestion": "개선 방법 또는 수정 코드"
  }
]

## 중요 규칙
- 문제가 없으면 빈 배열 []을 반환하세요
- 칭찬이나 잡담은 생략하세요
- 스타일 취향(세미콜론 유무 등)은 지적하지 마세요
- 실제 버그 위험이 있는 것만 지적하세요"""
</code></pre>
<h3>3.3 LLM 호출 및 결과 게시</h3>
<pre><code class="language-python">
import json

def review_file(client: OpenAI, filename: str, diff: str) -&gt; list:
    """파일 하나의 diff를 분석합니다."""
    response = client.chat.completions.create(
        model="gpt-4o",
        temperature=0.1,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": f"파일: {filename}\n\n```diff\n{diff}\n```"}
        ]
    )
    content = response.choices[0].message.content
    try:
        return json.loads(content)
    except json.JSONDecodeError:
        return []

def post_review_comments(issues: list):
    """분석 결과를 PR 코멘트로 게시합니다."""
    gh = Github(os.getenv("GITHUB_TOKEN"))
    repo = gh.get_repo(os.getenv("REPO_NAME"))
    pr = repo.get_pull(int(os.getenv("PR_NUMBER")))

    if not issues:
        pr.create_issue_comment("AI 리뷰 완료: 특별한 문제가 발견되지 않았습니다.")
        return

    severity_emoji = {
        "critical": "🚨",
        "warning": "⚠️",
        "suggestion": "💡"
    }

    body = "## AI Code Review 결과\n\n"
    for issue in issues:
        emoji = severity_emoji.get(issue["severity"], "📝")
        body += f"### {emoji} {issue['file']} (L{issue.get('line', '?')})\n"
        body += f"**문제:** {issue['issue']}\n\n"
        body += f"**개선안:** {issue['suggestion']}\n\n---\n\n"

    pr.create_issue_comment(body)
</code></pre>
<h3>3.4 메인 실행 함수</h3>
<pre><code class="language-python">
def main():
    client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
    diff_text = get_pr_diff()
    files = split_diff_by_file(diff_text)

    all_issues = []
    for filename, diff in files.items():
        if filename.endswith((".lock", ".json", ".md")):
            continue
        issues = review_file(client, filename, diff)
        all_issues.extend(issues)

    post_review_comments(all_issues)
    print(f"리뷰 완료: {len(all_issues)}개 이슈 발견")

if __name__ == "__main__":
    main()
</code></pre>
<p><code>.lock</code>, <code>.json</code> 등 리뷰가 불필요한 파일은 건너뛰도록 필터링합니다.</p>

<h2>6. 실전 팁과 주의사항</h2>
<h3>6.1 비용 관리</h3>
<p>대규모 PR에서 파일이 30개 이상 변경되면 API 호출 비용이 급증합니다. 파일당 diff 크기를 제한하거나, 변경량이 큰 PR은 사람이 직접 리뷰하도록 분기 처리하세요.</p>
<pre><code class="language-python">
MAX_DIFF_CHARS = 4000

for filename, diff in files.items():
    if len(diff) &gt; MAX_DIFF_CHARS:
        diff = diff[:MAX_DIFF_CHARS] + "\n... (이하 생략, 전체 리뷰는 수동으로 진행해주세요)"
</code></pre>
<h3>6.2 Hallucination 대응</h3>
<p>AI가 존재하지 않는 버그를 지적하는 경우가 있습니다. severity를 표시하여 개발자가 우선순위를 판단할 수 있게 하고, "AI 리뷰는 참고용이며 최종 판단은 개발자가 합니다"라는 면책 문구를 추가하는 것을 권장합니다.</p>
<h3>6.3 팀 컨벤션 반영</h3>
<p>프롬프트에 팀 고유의 코딩 규칙을 추가하면 더욱 유용합니다. 예를 들어 "우리 팀은 에러 처리 시 반드시 커스텀 에러 클래스를 사용합니다" 같은 규칙을 시스템 프롬프트에 포함시키세요.</p>
<h2>결론: 사람과 AI의 역할 분담</h2>
<p>AI 코드 리뷰어는 사람을 대체하는 것이 아니라, <strong>사람이 더 중요한 일에 집중하게 해주는 도구</strong>입니다. AI가 기계적인 검사(null 체크, 타입 안정성, 보안 패턴)를 담당하고, 사람은 비즈니스 로직의 정합성, 아키텍처 적절성, 사용자 경험 같은 고차원적인 판단에 집중하는 구조가 이상적입니다.</p>
<p>오늘 소개한 코드를 기반으로 여러분의 저장소에 AI 리뷰어를 도입해보세요. 작은 프로젝트에서 시작하여 프롬프트를 점진적으로 개선하면, 팀 전체의 코드 품질과 리뷰 속도를 동시에 높일 수 있습니다.</p></article>
